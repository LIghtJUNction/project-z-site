z64

处理 Base64 与 Base64URL 的编码、解码与校验。

Strict RFC 4648 Base64 and Base64URL for caller-owned buffers. Always no_std, using only core: no dependencies, allocation, build script, or external runtime. Stable Rust; MSRV 1.89.0. MIT licensed.

rust
use z64::{decode, encode, Mode};

let mut text = [0; 8];
let n = encode(b"hello", &mut text, Mode::Standard).unwrap();
assert_eq!(&text[..n], b"aGVsbG8=");

let mut bytes = [0; 5];
let n = decode(&text[..n], &mut bytes, Mode::Standard).unwrap();
assert_eq!(&bytes[..n], b"hello");

Modes and buffers#

Mode Symbols 62 / 63 Incomplete final quantum
Standard + / Requires = padding
StandardNoPad + / Forbids =
UrlSafe - _ Requires = padding
UrlSafeNoPad - _ Forbids =

Complete quanta have no padding in all four modes. Symbols 0–61 are shared; the other alphabet's symbols 62/63 are rejected. Whitespace, line breaks, misplaced padding, impossible lengths, and nonzero unused bits are errors.

encoded_len(n, mode) returns the exact size, or None on overflow. decoded_capacity(n) returns Some of a safe upper bound for every usize, without validating syntax. Terminal padding can reduce the exact decode capacity. Both conversions return the actual written length. Exact-sized, unaligned slices are supported; no readable or writable buffer tail is required.

Error contract#

All positions are zero-based byte offsets in the original input. Decode precedence:

  1. Impossible length: padded input must be divisible by four; unpadded input must not have remainder one. InvalidLength.index is the end-of-input offset.
  2. Output capacity, calculated using length and at most two terminal = bytes in padded modes. OutputTooSmall reports that required size even if content is invalid.
  3. First illegal alphabet byte or misplaced =, from left to right.
  4. Nonzero unused bits at the last alphabet symbol (NonCanonical).

Length/capacity errors leave output unchanged. On a content error at index, only complete decoded quanta before that quantum may have changed: at most output[..(index / 4) * 3]. That prefix is unspecified on error. The rest remains unchanged. Successful calls change only output[..written].

Scope#

The specification is RFC 4648 §§3–5 and §10. There is no MIME handling, whitespace skipping, custom alphabet, streaming I/O, CLI, serde integration, or other encoding format.

Backends and reproducibility#

The scalar path uses paired encoding lookups and an eight-symbol SWAR decoder. AVX-512 VBMI, AVX2 and AArch64 NEON accelerate conversion. VBMI uses masked loads/stores for partial vectors; scalar code handles the final incomplete quantum. On x86-64, a cached core::arch CPUID/XGETBV check establishes CPU and OS support, including opmask and ZMM state before selecting AVX-512. SGX, bare-metal/UEFI, and 32-bit x86 use compile-time features. AArch64 uses NEON only when enabled by the target. Other targets use scalar code. No API requires unsafe.

force-scalar, reference, no-avx512, no-runtime-detect, and no-short-path are verification and benchmark controls. reference retains the simple scalar implementation. No feature changes the accepted language, error precedence, or dependency graph. Rust 1.89 is required for stable AVX-512 intrinsics; the public API is unchanged.

The independent comparison project pins current baseline versions, checks strict semantics, and retains raw samples and environment data. Performance results include both wins and losses for generic and native builds. The recorded measurements use warm buffers on a shared Xeon with AVX-512 VBMI; they establish no portable speed guarantee. The 2x target against the strongest current competitor remains unmet. Shared-runner smoke results check correctness and are not used for performance conclusions.

CI and publishing#

CI tests stable and MSRV on x86-64 and AArch64 runners, checks bare-metal targets, runs Miri on scalar code, and audits the zero-dependency package boundary. The comparison workspace is excluded from the published crate.

Set the repository Actions secret CARGO_REGISTRY_TOKEN. A vX.Y.Z tag matching Cargo.toml triggers full checks on its resolved commit, package verification, and cargo publish --locked. The Publish workflow can also select an existing tag manually. Missing credentials, mismatched versions, or failed checks stop publication. GitHub Release creation follows confirmed crates.io publication.
