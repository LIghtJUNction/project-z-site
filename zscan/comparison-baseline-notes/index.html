Commits were read from the published crates' .cargo_vcs_info.json. Checksums are also in the independent comparison/Cargo.lock. memchr keeps its default features and runtime SIMD detection; disabling std would weaken the baseline.

memx reverse substring mismatch#

The first correctness smoke run, before optimized zscan measurements, found that memx 0.2.2 can omit the candidate at haystack.len() - needle.len(). Its first-byte reverse path initializes curr_idx to that index but searches the exclusive slice [..curr_idx]. When both slices have the same length, it skips the search entirely. The issue appears in both its scalar and x86 paths.

Minimal reproduction with the pinned dependency:

rust
let haystack = b"\xffA";
let needle = b"\xffA";
assert_eq!(memchr::memmem::rfind(haystack, needle), Some(0));
assert_eq!(zscan::rfind(haystack, needle), Some(0));
assert_eq!(memx::memrmem(haystack, needle), None); // comparator bug

The harness does not patch memx or remove cases. It retains memx/rfind timings and records each result's correct flag, but marks all memx/rfind rows eligible=false so that an incomplete search cannot win a speed comparison. Other memx operations, zscan, and memchr must match independent reference loops or the run stops. The remaining forward and byte memx results provide a second optimized baseline; memchr remains the primary baseline for every API.

Source: memx 0.2.2 reverse implementation and scalar implementation.
