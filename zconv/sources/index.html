Pinned design study#

Repository: https://github.com/LIghtJUNction/cortexfs

Commit: 84f349c97bc2f6a611109686a02e21de3800042a

Directory: crates/cortexfs-protocol

Read: borrowed.rs, bridge.rs, direct.rs, context.rs, event.rs, request.rs, response.rs, semantic.rs, openaichat.rs, openairesponses.rs, gemini.rs, and the crate README.

Borrowed wire views, a separate semantic model, explicit context ownership and provider namespaces are the design ideas reused. zconv is independently implemented with caller-owned storage and has no dependency on cortexfs-protocol. Identity conversions validate their input. Automatic fallback is restricted to capability errors; malformed input and capacity errors remain errors.

Registry check#

Before initialization, GET https://crates.io/api/v1/crates/zconv?nocache=20261110 with an identifying User-Agent returned HTTP 404 and {"errors":[{"detail":"crate zconv does not exist"}]}. The sparse registry entry https://index.crates.io/zc/on/zconv was also absent. The initial no-User-Agent request returned HTTP 403; that response was not treated as evidence of name availability. The release gate repeats the API check before publication; name availability is not a reservation.

Interpretation rules#

Gemini Interactions is a separate resource: its previous_interaction_id belongs to its provider namespace. It cannot become an OpenAI previous_response_id. Current Interactions uses steps, including model_output, thought, function_call, and function_result, and step-based streaming events.

Anthropic 2026-10-21 removes sampling parameters. Adapters must reject requests that would emit temperature, top_p or top_k for that version, even if a value matches an earlier default. These are protocol version differences, not vendor extensions.

Specifications define the supported wire contract. Additional model-specific validation and network headers remain the caller's responsibility.

The new resource module is an independent implementation of wire contracts, not an upstream type re-export. Embedding vectors remain floating JSON values or base64 strings; numeric token accounting remains integral. Files bytes may be null, and binary file content has no JSON schema. Batch JSONL validates individual envelopes but cannot establish file-wide custom ID uniqueness without caller state. Legacy image variation encoding preserves a historical wire format and does not assert that a retired endpoint or model is available on a provider.

Defaults and token-accounting differences#

Chat function definitions without an explicit strict setting use best-effort calling. Responses attempts schema normalization into strict mode when possible, otherwise falls back to best effort. Cross-conversion from Chat therefore writes strict:false; a Responses source with unresolved missing/null strict requires the caller to resolve the mode in IR before cross-conversion. Same-format IR retains the source's field-presence state. Explicit boolean settings are retained only where the target can express that guarantee.

Anthropic's input_tokens excludes its separately reported cache read/write counts. The IR's input total includes them. Gemini's visible output count excludes thought tokens; the IR/OpenAI output total includes them. These conversions use checked integer addition/subtraction. The Interactions v1 reference example with input 7, visible output 23, thought 49 and total 79 is a regression fixture: canonical output is 72, and encoding back to Gemini restores visible output 23.

The documented OpenAI Responses SSE union includes completed, incomplete and failed lifecycle events. A similarly named cancellation webhook is not reused as a stream event. Length and safety finishes preserve distinct incomplete reasons instead of being labeled successful completion.
