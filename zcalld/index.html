zcalld

本地模型网关，集中管理提供方、路由规则与模型调用。

A native local AI gateway for Linux, macOS and Windows, built on zcall, zconv, zplugin and zsys.

The CLI daemon owns transport, bounded queues, credentials and protocol conversion. Privacy, community providers, model-group decisions and desktop notifications are optional plugins. zcall-gui is a separate native application built with zgpui; closing it leaves the gateway running. There is no embedded browser in either application. The optional compatibility package supplies the Go privacy and advanced-rule workers and one lazy Bun host for existing JavaScript community plugins. zcall-omarchy is a second, independent frontend that uses Omarchy's native plugin and menu interfaces without another background gateway.

The daemon reuses zcall's optional server module for HTTP framing, protocol conversion and caller-key parsing. zcalld owns worker queues, native plugin instances, upstream transport and bounded gzip/zstd decoding; each worker retains its own plugin state.

Install#

On Arch Linux, choose one core package and add the capabilities you use:

sh
paru -S zcalld-bin
# Source build alternative: paru -S zcalld
paru -S zcalld-compat    # Privacy model, community plugins and subscription accounts
paru -S zcall-gui       # Optional native desktop application
paru -S zcall-omarchy   # Optional Omarchy bar and terminal menu frontend

Releases provide Linux x86_64/aarch64, Windows x86_64 and macOS Apple Silicon/Intel archives with platform-native plugin libraries. Linux and macOS use the system libcurl; the Windows archive includes its TLS transport DLLs. Incoming gzip/zstd requests use native codecs: distribution libraries on Linux, static zstd plus system zlib on macOS, and static codecs on Windows. These are real operating-system dependencies, not an embedded browser runtime.

sh
zcalld init
# Edit the generated provider and route to match an available upstream.
zcalld check --json
zcalld serve

The default configuration uses an Ollama-compatible upstream. zcalld does not download or execute an LLM. Configuration follows --config, ZCALLD_CONFIG, then the platform user configuration directory. Run zcalld --help for the exact local path and command list.

Preserve an existing Magpie setup#

Migration first creates a private copy; it does not stop Magpie or change agent settings:

sh
zcalld migrate magpie --json
zcalld migrate magpie --apply --json
zcalld migrate verify --json
zcalld check --json

The importer preserves public model IDs and catalog metadata, routes, accounts, enabled community packages, the reversible privacy key, custom rules and history. It reports unresolved routes or unsupported rules explicitly. The old TCP address can remain unchanged while zcalld's own CLI and GUI prefer a private Unix socket on Linux and macOS.

See MIGRATION.md for the service transaction and rollback. Credential refresh ownership matters: an active native Codex login remains externally managed and is reread for each request. The gateway does not race another process to rotate that account's refresh token. Explicit handoff requires the recorded original owners to have exited.

Configure and use#

ini
[server]
listen = 127.0.0.1:9415
unix_socket = auto
workers = 4
queue = 16
token_env = ZCALLD_GATEWAY_TOKEN

[provider cloud]
base_url = https://api.example.com/v1
protocol = chat
api_key_env = CLOUD_API_KEY

[route coding]
provider = cloud
model = upstream-model

Put secrets in the private credentials file beside the configuration, as NAME="value" assignments. Environment values take precedence. Provider credentials and caller credentials are separate; incoming authorization, cookies and query keys are not forwarded upstream. A non-loopback listener requires a LAN-capable credential.

Protocol names are chat, responses, anthropic, gemini, completions and interactions. Native per-protocol endpoint overrides accept a base URL or a complete endpoint URL. Same-protocol forwarding retains provider extensions. Cross-protocol conversion uses strict zcall semantics and rejects unsupported information loss.

Endpoint Purpose
/v1/chat/completions, /v1/responses OpenAI-style generation
/backend-api/codex/responses Codex ChatGPT Responses ingress; shared authentication, privacy and routing
/v1/messages Anthropic Messages
/v1beta/models/{model}:generateContent Gemini generation
/v1beta/models/{model}:streamGenerateContent Gemini streaming
/v1/completions, /v1beta/interactions Additional protocol ingress
GET /v1/models Public routes with preserved catalog metadata
GET /backend-api/codex/models and bound account metadata paths Optional native Codex metadata; disabled until explicitly configured
GET /healthz Readiness
POST /mcp/zcalld/tools, POST /mcp/magpie/tools Optional community-tool MCP; the legacy address remains valid

Management#

sh
zcalld status --json
zcalld providers list --json
zcalld keys list --json
zcalld providers add work --base-url https://api.example.com/v1 --api-key-stdin
zcalld routes list --json
zcalld groups set group/work --members work/model-a,work/model-b --mode rotate
zcalld agents detect --json
zcalld agents apply claude --route group/work --json
zcalld agents revert claude --json
zcalld plugins list --json
zcalld plugins mcp show --json
zcalld accounts list --json
zcalld plugins quota list --json
zcalld privacy show --json
zcalld desktop show --json
zcalld profiles save work --json
zcalld library list --json
zcalld library targets --json
zcalld usage enable --json
zcalld usage summary --model group/work --json
zcalld usage export --file usage-export.jsonl --json
zcalld update check --json

Provider --api-key-stdin updates an exclusive credential reference in place. If another provider, header or gateway token shares that reference, the edited provider receives a separate credential slot and the other references keep their saved value. New slots avoid existing saved credentials, configuration references and environment variables. Use --api-key-env NAME to select an existing credential instead; it cannot be combined with --api-key-stdin. Environment values still take precedence over saved credentials. Invalid or oversized credential files are rejected before either file is changed.

Model edits through providers add/edit --model or routes set --model use the configuration reader's INI value rules: the parsed model must be nonempty, contain no control characters and fit in 512 UTF-8 bytes. Provider model and route errors are rejected before reading --api-key-stdin, creating backups or writing files. Group routes preserve the selected model's literal quotes and surrounding spaces.

Provider add/edit validates the effective base URL and protocol together before reading credentials or writing files. Route and group edits preserve the selected provider's literal name, including quotes or spaces. Configuration updates and removals recognize section headers with surrounding whitespace, while keeping whitespace inside names distinct.

Managed model groups own their public route names. Direct route edits and provider model options cannot overwrite or remove a group route. Removing a member route, or a provider that still supplies a group route or member, is rejected before credential input, backups or file writes. First update the group's members with groups set, or remove the group with groups remove. These route-changing commands also reject malformed routing.json instead of treating it as an empty group list.

Group definition files preserve member weight and off settings and literal route names, including commas. Explicit settings replace the selected member's values; omitted settings keep them. Invalid new weights or disabled-state values fail before files or backups change. See the group configuration examples.

Agent edits preserve unrelated fields and keep exact-byte backups. Revert refuses to overwrite later user edits unless explicitly forced. Account controls operate on the actual private compatibility-host store. Community packages must be deliberately enabled; trusted native libraries run inside the daemon process.

The agent library manages MCP definitions, instruction sets and skill files separately from gateway providers. Preview/apply/revert keeps exact owned bytes and refuses conflicting user edits. Skills can be fetched from an HTTPS or local Git repository, restricted to one subdirectory, and updated from a remembered branch, tag or commit. Fetching never checks out or runs repository code; later local edits require an explicit force before replacement. Community MCP uses the optional HTTP plugin interface and the same shared Bun process as community providers; initialize and ping do not start that process. Caller-key permissions remain separate from upstream credentials.

Privacy runs before model-group classification. JSON and fragmented SSE responses restore masked values. If a required privacy worker is unavailable, requests fail closed before upstream generation. With compatibility 0.1.3 or later, private daily audit files continue recording detection metadata and per-agent counters; request bodies and restoration maps are not stored. Audit writes have size and retention bounds. A disk-write failure is reported without discarding a valid redacted request. Group modes include order, smart, rotate, usage, pace, weight and drain; turn affinity is bounded. Explicit upstream 429/503 responses may select another member before downstream headers are committed, with at most four total attempts. An already-started stream or an ambiguous network failure is never replayed. Advanced rules support IANA time zones, RE2 message conditions and trusted workspace conditions through a lazy optional worker; ordinary groups do not start it.

Caller-key management provides keys add, rotate and revoke; new key material is accepted only through --api-key-stdin. Saved key changes require a gateway restart and never restart the service automatically.

plugins quota list reads local saved results. With the optional compatibility helper 0.1.6 or newer, plugins quota refresh --account ACCOUNT_ID explicitly updates one supported account; ordinary status and quota-list commands do not refresh credentials or contact providers.

Usage recording counts upstream attempts, including retries, and exposes input, output, cache and reasoning token details. usage enable validates the native observer and destination before saving; usage disable retains history. Both report whether an explicit gateway restart is required. The GUI provides recording controls, retained totals, refresh and a separate restart action. Summaries support model and time filters, scan native or migrated history with bounded record buffering, and skip records over 1 MiB, excluding LF or CRLF. usage export --file PATH preserves original bytes and refuses existing destinations. See the usage boundary validation and Magpie alignment matrix for tested scope and remaining gaps.

Desktop integration is a separate native plugin, disabled by default. It can keep the device awake while an agent is working and deliver usage, balance, renewal, expiring reset-credit, first-mask and completed-turn notices. Only existing fresh observations are used; notifications add no provider polling. A completed turn requires a terminal success that was fully delivered to the client; tools, cancelled requests and truncated streams do not count as completed answers.

Use zcalld desktop configure --file SETTINGS.json for explicit settings, or desktop plan --source /absolute/path/to/magpie followed by desktop sync --source PATH --expect-plan HASH to preserve existing preferences. Inspection and configuration validation do not send notifications or acquire an inhibitor. Saved changes take effect after the gateway is restarted. Windows and macOS notification identities require the native platform's explicit registration or permission step; their packaged helper never requests that permission implicitly.

Services#

Linux user service, after configuration:

sh
systemctl --user daemon-reload
systemctl --user enable --now zcalld.service
journalctl --user -u zcalld.service

The Linux system service runs as the dedicated zcalld user and reads /var/lib/zcalld/config.conf. Initialize that private state directory before starting it; /etc/zcalld/config.conf is a template. Both units use readiness notification, private socket permissions and a 60-second stop budget so an in-progress credential rotation can finish writing.

On macOS, zcalld service start manages a per-user launchd agent. On Windows it manages a per-user scheduled task. service status queries the actual platform manager and checks gateway health. Unix sockets are used where supported; Windows clients use loopback TCP.

Build, submodules and release#

sh
git clone --recurse-submodules https://github.com/LIghtJUNction/zcalld.git
cd zcalld
make check
make package
make bump BUMP=patch
make release
# Or: gh workflow run bump.yml -f bump=patch

Use Rust 1.100.0, Python 3.11+, a native compiler, and libcurl, zstd and zlib development libraries. On macOS, add the Homebrew zstd library directory to RUSTFLAGS so the static archive can be found. The native release workflow provides the exact Windows static-codec build recipe. Project Z library dependencies use their public Git repositories, with exact revisions pinned in Cargo.lock. Git submodules retain the matching source snapshots for coordinated development. The optional GUI, Omarchy frontend and compatibility repositories are also submodules; they keep independent releases.

Day-to-day checks run locally. Formal release workflows validate five native targets, including real privacy, routing and community MCP worker calls, publish versioned archives plus SHA256SUMS, and update source/binary AUR recipes. Linux also runs the migration transaction and rollback fixtures before publication. Source archives recursively include the exact tracked submodule commits; private and untracked development files are excluded. The bump command updates workspace versions, internal dependency version constraints, the lockfile and changelog as one recoverable operation. Upgrading a shared library is a separate, deliberate change to its lockfile revision and matching submodule pin.

Before tagging a Windows-specific correction, dispatch the Release workflow on the candidate branch with candidate=true, tag=<full commit SHA> and platform=windows. This runs the complete Windows build, recovery, control, runtime, compatibility and archive checks without publishing. Platform selection only narrows candidates; formal releases always validate all five native targets.

RELEASING.md describes publishing and recovery. PLUGINS.md describes the SDK. PERFORMANCE.md contains measured daemon baselines, with versions and workload limitations. GUI renderer and native-platform evidence live in its own repository. No client pricing table, subscription tier or paid feature gate is built into these projects.

Deployment acceptance, 2026-11-20 records the installed 0.2.4 gateway with 0.1.5-2 compatibility workers: migration preservation, real JSON/SSE generation, package provenance and full-process-tree memory including swap. Its scope differs from the historical minimal-daemon benchmark.

MIT licensed. Magpie compatibility code retains upstream notices in the optional compatibility repository.

Codex transport compatibility#

Responses clients that negotiate WebSocket transport can fall back to HTTP/SSE through the gateway. See the negotiation contract and local validation for the supported boundary.
