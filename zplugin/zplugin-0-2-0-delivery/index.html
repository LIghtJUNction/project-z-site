zplugin 0.2.0 交付报告

日期：2026-11-13，Asia/Taipei。

本轮范围#

zplugin 0.2.0 与 zplugin-macros 0.2.0 已正式发布到 crates.io，并完成公开包的独立安装验收。 本轮新增跨库异步任务、C/C++/Zig 接口生成，以及稳定结构体、枚举、拥有型资源和回调。 最终提交通过全部三平台门禁，tag、Release 和两个公开包使用同一已验证版本。 核心仍是默认 no_std、无需分配器、零第三方运行时依赖的原子化库，不包含执行器、 插件市场、目录监听器或业务框架。

能力 已交付实现 明确边界
跨库异步 OwnedTask<T>、Task<T>、poll/cancel/release、可 retain 的线程安全 waker，宿主可 .await T: AbiValue；不传递原生 Future/Waker 布局，不安装异步运行时
跨语言生成 共享 Rust trait 生成完整 C 头文件、布局、方法签名与描述符初始化器；Zig 翻译该头文件 同一目标平台 C ABI；不是跨平台通用二进制
稳定值 #[abi_type] 结构体、嵌套结构体、无载荷及带载荷枚举，完整递归 schema 检查 首版不接受泛型、引用、数组、拥有型容器、bool/char/usize/isize/128 位字段
拥有型资源 OwnedResource、宿主 Resource、资源 ID/版本、原库释放函数和独立存活凭据 应用定义操作码及缓冲协议；不跨边界传 Rust 分配器或 trait object
反向回调 Callback/CallbackRef、显式 retain/release、重入检查和 panic 污染状态 普通回调限创建线程；只有 waker 的通知操作允许跨线程

旧入口 zplugin_entry_v1、既有同步描述符和方法签名未改变。扩展表使用独立的长度与 版本前缀；应用新增方法仍应升级业务接口版本，不能偷偷改变已冻结的函数表。

使用与复现#

安装时按需要显式启用功能：

sh
cargo add zplugin@0.2.0 --features std,macros,hot-reload

只需要协议或手工句柄时，可以关闭所有默认功能；alloc 提供 Rust future、闭包回调、 拥有型资源等便利适配，std 额外支持可展开 panic 的捕获。过程宏的 syn、quote、 proc-macro2 及其传递依赖只用于编译，不是运行时依赖。

完整独立项目与构建步骤：

  • Rust 异步共享接口、插件和宿主。
  • C/C++/Zig 插件和 Rust 宿主。
  • 扩展 ABI、所有权、线程和取消协议。
sh
python3 scripts/check.py
python3 scripts/check.py --cross-version
python3 scripts/legacy.py
python3 scripts/foreign.py --install-zig
python3 tools/bench/run.py docs/benchmarks/v0.2.0
python3 tools/bench/extensions.py

异步代理在相同 C waker 和生命周期语义下比缓存 C poll 多 1.802 ns/次。工作线程 创建/取消/join/释放的三次 p50 为 8.478–14.242 µs；这些结果受调度影响，不构成取消时限。 异步测量每行净存活字节增量为零，结束时插件计数字节归零，并验证协作式关闭成功。

创建、首次桥接和更换 waker 会分配，不能把“稳定 poll 为零分配”扩展成“所有异步操作零分配”。 计数器不覆盖系统加载器或 OS 线程内部的分配。4 KiB/1 MiB 的运行间波动明显，不据此宣称 比所有缓存函数指针或 libloading 普遍更快。

完整性能报告 包含全部对照、分配/内存、加载、绑定、创建/销毁、热切换、延迟测量方法和六份原始 CSV。 测量在版本号递增前完成；最终发布仅做版本同步，运行时及示例的功能源码没有另行替换。

安全与支持边界#

加载本机代码仍是明确的 unsafe/信任边界。ABI 检查发现不兼容，不隔离恶意代码、 内存破坏、panic=abort 或本机崩溃。插件自己负责网络、文件、运行时、线程及业务状态。

普通代理、任务的 poll/cancel/drop、资源和一般回调均采用创建线程模型，不声明 Send/Sync。 waker retain/wake/release 可以跨线程。异步任务必须拥有调用结束后仍需要的数据，不能把 调用期借用保存到 future。异步结果目前限 AbiValue，不直接返回拥有型缓冲或资源。

默认固定驻留最保守。物理卸载依赖显式的协作式安全承诺：必须释放对象、资源、任务和回调， 并等待所有工作线程、注册项以及最后一次回调/析构的返回路径退出。示例通过 join 实现； 不能因为引用计数为零就假定任意外部执行器已经停机。清理失败时保留库，不用超时强制卸载。

C/C++/Zig 示例使用平台系统 ABI。Zig 验证固定 Linux/Windows 0.17.1、macOS 0.15.2； macOS 由 Zig 生成 PIC 对象，再由当前 Apple SDK 的 C 驱动链接。测试某一系统版本不代表 已验证所有更旧系统，交付插件必须遵守自己的目标架构、部署版本和系统库要求。

结论与证据自检#

  • 功能贡献：提供稳定边界与生命周期原语，不包装成完整异步框架。
  • 表达清晰：接口、ABI、crate 和业务版本分开；借用、拥有、通知和执行分开。
  • 实验强度：保留静态/缓存 C/libloading 对照，初始化与稳定调用分测，公开不利波动。
  • 验证范围：真实原生库、跨 Rust 版本、错误与资源退出路径均有可执行测试；最终原生矩阵和公开包安装均已通过。
  • 设计正确性：不承诺自动关闭任意执行器、强制卸载、不可信代码隔离或未测平台性能。
