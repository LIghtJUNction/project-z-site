zharness

复用上下文、工具循环、hook 与协作执行原语。

Caller-buffered primitives for developer-owned AI harnesses: context windows, model/tool turns, hooks, output transforms and multi-agent coordination. The core is no_std, forbids handwritten unsafe Rust and directly depends on zcall = "=0.4.0", zplugin = "=0.3.1" and zguard = "=0.1.0" with default features disabled. zplugin's official macro generates the native interface and introduces compilation-only parser dependencies. Native library loading is shared through zsys = "=0.1.1", a transitive dependency of zplugin. The default/native runtime graph stays within Project Z crates; the explicit wasm feature adds zplugin's Wasmi sandbox. The dependency audit checks exact Z versions, registry sources and a single resolved package for each name.

The protocol layer consumes zconv 0.4.0 through zcall and retains trusted native and untrusted Wasm plugins with named operations, mixed-backend routing, explicit disabling/replacement and existing authorization hooks. It retains skills, typed lifecycle channels, provider-bound tool signatures and conversation/model/request/response primitives. The library does not start an HTTP client or agent runtime. Development uses Rust 1.100.0; MSRV remains 1.99.1, edition 2024.

To use the published package:

toml
[dependencies]
zharness = "=0.6.0"

Default features enable filesystem skill discovery and native path loading. Set default-features = false to use the no_std core. Add features = ["wasm"] for sandboxed plugins. This feature needs an allocator but does not imply std; native plugin loading continues to require trusted code.

Response lifecycle hooks distinguish raw reasoning from summaries and preserve provider-owned Anthropic blocks, citation deltas and usage metadata as separate actions. Those server tool blocks never enter the local execution queue. The re-exported zharness::zcall contract also exposes structured tool results, continuous usage configuration and the api resource codecs.

Boundary#

The library maintains bounded state and returns actions. Your application owns I/O, model selection, authorization, scheduling and persistence. No HTTP client, background worker, retry engine, tokenizer, summarizing model or database is started implicitly. MCP is developed independently in zmcpio; this repository contains no MCP integration directory or cross-repository build dependency.

Native security guardrails#

Use Prepared::execute_guarded and Command::execute_guarded to apply zguard at the actual execution boundary. Policies deny unmatched calls, separate tool and command permissions, require host-issued approvals where configured, and check call/input limits. A failed audit write blocks execution. Models cannot grant themselves permission through argument fields.

Authorization and the executor adapters are single-attempt values. Reuse the session Guard to preserve quotas, and construct a new Authorization with current host time for each call. Existing low-level execution APIs retain their explicit host-authorization contract. See GUARDRAILS.md for request binding, plugin routing, privacy and the complete compiled example.

sh
cargo run --locked --example guarded_execution

Native extensions#

plugin::Plugin exposes zplugin's actual native loader. Load an explicitly chosen trusted library, create ExtensionApi's typed proxy, then call operations with borrowed input and caller-owned output buffers. The same proxy implements Executor, so it works with the existing tool registry and execution hooks.

The v1 extension interface has one operation: call(operation, input, output). The library checks returned lengths and can validate UTF-8; the application owns operation semantics, payload schemas, scheduling, permissions and recovery. There is no automatic plugin scan, tool registration, execution or reload loop. See PLUGINS.md for loading, plugin authoring, lifecycle and examples.

Untrusted Wasm and mixed plugin tools#

Enable wasm, then use plugin::wasm::WasmExtension::load with an explicit interface ID/version, resource limits and a host-owned name-to-operation map. The safe loader accepts zplugin's import-free Wasm32 protocol. It denies WASI, filesystem/network/host imports, checks memory ranges and meters execution fuel. The adapter implements the same Executor used by native extension proxies.

plugin::Router borrows explicit Route and Slot arrays. A public tool name selects a slot and backend operation; set_enabled denies a slot without invoking it, and replace switches a previously validated executor at a call boundary. Execute through Prepared::execute_with_hooks to authorize the public tool name before routing. Unknown or disabled tools fail closed, with no fallback or retry.

sh
rustup target add wasm32-unknown-unknown
python3 scripts/wasm.py

This builds a real allocator-free guest and runs both a sandbox-only host and a host routing tools to native and Wasm plugins. WasmExtension::reload validates a fresh same-interface instance before replacement; failure retains the current state. Runtime failures preserve detailed diagnostics through last_error().

Wasm is a separate synchronous byte-buffer ABI. Native tasks, pointers, resources and callbacks are not forwarded into it. Isolation depends on the Wasm engine; guest-memory limits do not cap process RSS, and fuel does not time module compilation. Use additional process isolation for stricter resource/threat models. See the complete contracts and examples.

The Wasm adapter measurements compare matched zplugin, Executor and Router calls with raw samples and allocation counts. They distinguish warmed calls from loading and do not claim process RSS limits or end-to-end agent latency.

Native skills#

SkillPaths::from_env(project) combines project and global skills with any directories in SKILLS_PATH. Earlier valid names win, while unrelated global skills remain available. The environment follows the host PATH syntax and precedes the defaults. Use prepend or push for software-specific directories, or SkillPaths::new(roots) for an exact search plan.

sh
export SKILLS_PATH="$PWD/.agents/skills:$HOME/.claude/skills:/opt/editor/skills"
cargo run --locked --example skills

Discovery retains each skill's name, description and location. Summary generation writes escaped XML into your buffer; selected bodies and resources load on demand. The default std feature enables the filesystem adapter. Disabling default features retains the borrowed parser and summary writer with no alloc or I/O. See SKILLS.md for Rust examples, precedence, diagnostics and limits.

Grouped lifecycle hooks (0.2.3)#

Use a small typed event rather than a hundred methods in one Hooks trait. The families are conversation, model, prompt, request, response, tool, context, agent, persistence and runtime. Gates decide; interceptors change copied candidates; observers record facts. Observers get payload metadata by default, with explicit content opt-in. Tuples compose statically; there is no global mutable registry.

Lifecycle::run wraps an actual operation. begin/finish supports application- owned async work and out-of-order completion without an async runtime. Native adapters already cover user acceptance, message edits/deletes, model and reasoning changes, request building/sending, stream consumption and assistant finalization. Storage, routing, rate limits and other application-owned work use explicit wrappers, not fictitious automatic interception. See LIFECYCLE.md for the full 97-action matrix, compiled examples, privacy and failure/replay contracts.

An accepted send is not provider receipt. A model turn ending in WaitingTools is not a final assistant reply. A paused stream event must be replayed before it is counted as accepted. ModelSettings records intent for future requests; provider capability checks and wire mappings still belong to the application and zcall.

Context without an owned conversation heap#

rust
use zharness::context::{Budget, Context, Group, Message, Overflow};
use zharness::zcall::v1::{Content, Role};

let instructions = [Content::text("Use only approved tools.")];
let question = [Content::text("Review this change.")];
let system = [Message::new(Role::System, &instructions)];
let user = [Message::new(Role::User, &question)];
let mut slots = [None; 8];
let mut context = Context::new(
    &mut slots,
    Budget { limit: 4096, reserved: 1024 },
)?;
// Caller estimates for illustration; use the target model's tokenizer in production.
context.push(Group::new(0, &system, 16).pinned(), Overflow::Reject)?;
context.push(Group::new(1, &user, 20), Overflow::EvictOldest)?;
assert_eq!(context.tokens(), 36);
# Ok::<(), zharness::Error>(())

Keep related calls/results in one Group. Eviction/compaction never splits a group. Forks copy descriptors, not borrowed content; explicit summaries come from the application. Context::build delegates protocol representation and checked tool results to zcall instead of creating another provider adapter.

Drive a loop without surrendering control#

rust
use zharness::{ToolLoop, hooks::NoHooks, turn::{Action, CallSlot, LoopLimits}};

let mut slots = [const { CallSlot::<1024>::new() }; 4];
let mut flow = ToolLoop::new(7, &mut slots, LoopLimits::default());
let mut hooks = NoHooks;
assert_eq!(flow.next(&mut hooks)?, Action::CallModel { run: 7, round: 1 });
// The application has not sent a model request yet.
assert_eq!(flow.next(&mut hooks)?, Action::Pending);
# Ok::<(), zharness::Error>(())

Feed genuine zcall events to observe, then execute only approved Execute tickets. ToolReady is retained until WaitingTools is confirmed. Several tickets can finish out of order. Retain history/results, acknowledge the Session and commit each result explicitly before another model action is issued. No hidden loop performs network requests or retries side effects.

Execution and output processing#

Prepared::execute_with_hooks and Command::execute_with_hooks gate actual user executors, distinct from scheduling or history commitment. Pause/deny does not invoke an adapter. Nonzero command exits and business tool errors retain their status; invalid output or adapter failures remain errors. The core does not spawn processes, interpret shell strings or enforce adapter timeouts.

rust
use zharness::{bridge::Completion, hooks::{HookResult, NoHooks}};
use zharness::output::{Chain, DedupAdjacentLines, Truncate};

let original = Completion {
    call_id: "real-call-id",
    text: "error: missing config\nerror: missing config\n",
    is_error: true,
};
let mut scratch = [0; 1024];
let mut output = [0; 256];
let mut pipeline = Chain::new(
    DedupAdjacentLines,
    Truncate::new(256, "\n...[truncated]")?,
    &mut scratch,
);
let HookResult::Applied(reduced) = original.transform_with_hooks(
    "build", &mut pipeline, &mut output, &mut NoHooks,
)? else { unreachable!("NoHooks never pauses"); };
assert_eq!(reduced.text, "error: missing config\n");
assert_eq!(reduced.call_id, original.call_id);
assert!(reduced.is_error);
# Ok::<(), zharness::Error>(())

Reduction preserves identity/status. Retry failed output processing with retained raw input, not by rerunning the tool. JsonMinify validates through zcall; text truncation is explicitly lossy and does not promise valid truncated JSON or exact token savings. Custom semantic summaries remain an application decision.

Run from the source checkout#

sh
cargo test --locked --all-targets
cargo test --locked --doc
python scripts/examples.py
cargo run --locked --example conversation_hooks
cargo run --locked --example tool_loop
cargo run --locked --example command_hooks
cargo bench --locked --benches

The conversation example covers user approval, settings changes, real zcall request encoding, an in-memory send, recorded response parsing and explicit final persistence. Tool-loop tests cover real interleaved calls. Command hooks run controlled child processes on the host. No live provider credentials are required; these examples do not claim real network/model/database integration.

All proportional core storage is caller-owned. Generic callback code and adapters can independently allocate or cause side effects. Hooks are not a sandbox, IDs are not authentication, and leases do not provide external exactly-once execution.
