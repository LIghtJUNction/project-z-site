Zuse standard library

为 Zuse 提供绘图、分形、桌面操作、文字输入和计时函数。

Reusable Zuse functions for drawing, fractals, desktop setup, explicit text input, and timing. The std package is source code: installation stores a pinned Git commit locally, and import registers its functions. Desktop actions begin when a script calls them.

Version 0.1.0 requires Zuse 0.6.0 or later, with pkg, window anchors, mouse.stroke, draw.triangle, and bounded scalar programs. Use zuse --version and zuse schema to check the installed build.

Install and inspect#

Create a project directory, then add the tagged package:

sh
mkdir my-drawing
cd my-drawing
zuse pkg init my-drawing
zuse pkg add https://github.com/LIghtJUNction/zuse-std.git --rev v0.1.0
zuse -c 'import(path="pkg:std",as="std"); functions(namespace="std")'

Commit the project's zuse.json and zuse.lock.json. The manifest records the requested source revision; the lockfile records its full Git commit. Another checkout restores the locked sources with:

sh
zuse pkg install --locked

The package has no third-party package dependencies. Import uses installed files and does not fetch code or run installation hooks. Git transport and the package manager remain part of the installation process.

Import a module#

Import the whole library for std.desktop, std.drawing, std.fractal, std.input, and std.timing: 22 functions across five exports. Import one export when a script needs a smaller namespace:

zuse
import(path="pkg:std/drawing", as="art")
functions(namespace="art")

Function descriptions and parameter names are included in the catalog returned by functions. Arguments are named and required; the table below lists every public function. Source files are the authoritative implementation.

Export Function Behavior
desktop inspect() List windows and inspect held keyboard modifiers.
desktop focus(window_id) Focus the specified window and wait 200 ms.
desktop bind_canvas(name,window_id,x,y,width,height) Focus, borrow the system pointer, and create a window-local anchor.
desktop click(canvas,x,y) Click a local point with 30 ms input settling and 70 ms application settling.
desktop capture(window_id,path) Save a window screenshot at the requested path.
desktop release_canvas(name) Clear the named anchor and release the session's mouse handle.
drawing stroke(canvas,points,duration) Draw an open polyline with explicit timing.
drawing line(canvas,x1,y1,x2,y2) Draw a line in 180 ms.
drawing triangle(canvas,x1,y1,x2,y2,x3,y3) Outline three numeric vertices in one 240 ms stroke.
drawing rectangle(canvas,x,y,width,height) Outline a rectangle in 240 ms.
drawing circle(canvas,x,y,radius) Outline a circle with 64 segments in 360 ms.
drawing polygon(canvas,points,duration) Close and outline a polygon with explicit timing.
drawing arrow(canvas,x1,y1,x2,y2,head) Draw a line and an explicitly supplied arrowhead polyline.
fractal sierpinski(canvas,x,y,width,height,depth) Compute and draw a Sierpinski triangle using bounded Zuse recursion.
input type_in(window_id,text) Focus the specified window, wait 200 ms, then type into its current text target.
input key_in(window_id,key) Focus the specified window, wait 200 ms, then submit a key or chord.
input set_text(node_path,text) Focus an observed accessibility node and replace its text.
timing start(), stop(), status(), reset() Forward to the session timer operations.
timing pause(ms) Wait within the script's configured wait budget.

Draw on an observed canvas#

Observe the intended window and its canvas first. Replace WINDOW_ID and the region below with those observations; the numbers are examples. Select the application's brush, width, and color before executing drawing functions.

zuse
import(path="pkg:std", as="std")
std.desktop.bind_canvas(name="board", window_id="WINDOW_ID", x=160, y=180, width=640, height=480)
std.timing.start()
std.drawing.rectangle(canvas="board", x=40, y=40, width=240, height=140)
std.drawing.circle(canvas="board", x=160, y=110, radius=45)
std.drawing.arrow(canvas="board", x1=310, y1=110, x2=430, y2=110, head="410,90;430,110;410,130")
std.timing.stop()
std.desktop.capture(window_id="WINDOW_ID", path="canvas.png")
std.desktop.release_canvas(name="board")

The drawing functions use the application's current brush and left mouse button. They outline shapes; they do not set colors or fill areas. points and head use x,y;x,y strings. The arrow helper accepts explicit head vertices so callers can choose its shape. Numeric geometry, including recursive subdivision, can be calculated directly in Zuse expressions.

Coordinates are local to the named canvas anchor. The runtime rejects an anchor when its window identity, focus, position, dimensions, or scale changes. It does not track scrolling or zooming inside the page. Re-observe changed geometry before binding again. A completed input receipt means input was submitted; inspect the screenshot to confirm the application drew the intended result.

The fixed waits make these small compositions easier to reuse; they are not application-readiness detection. For long workflows, use the runtime's bounded observation and waiting primitives. Multiple scripts can retain functions and anchors in zuse shell; its idle timeout controls cleanup of the session.

Draw a fractal with Zuse expressions#

The fractal module computes every vertex with let, arithmetic, if/else, and recursive function calls. Each leaf uses one draw.triangle stroke. It contains no precomputed coordinate arrays and needs no external program to generate the geometry.

Observe the window and canvas first, select the application's brush and color, then replace the window ID and anchor region below. This example assumes an observed 755 × 646 canvas and passes the complete program to Zuse through stdin:

sh
zuse script - --max-steps 4096 --max-wait-ms 90000 <<'ZUSE'
import(path="pkg:std", as="std")
std.desktop.bind_canvas(name="board", window_id="OBSERVED_WINDOW_ID", x=160, y=180, width=755, height=646)
std.fractal.sierpinski(canvas="board", x=50, y=590, width=650, height=560, depth=5)
std.desktop.capture(window_id="OBSERVED_WINDOW_ID", path="fractal.png")
std.desktop.release_canvas(name="board")
ZUSE

x,y identify the left end of the base; height extends upward on the screen. Depth 0 draws one triangle, depth 2 draws 9, and depth 5 draws 243. Each leaf uses 60 ms of motion and two 10 ms settling waits, so depth 5 has a fixed drawing wait budget of 19,440 ms. Window checks and input dispatch add elapsed time. For a smaller namespace, import pkg:std/fractal with an explicit alias.

Validate the package#

These commands load declarations, inspect the catalog, and validate every public function without sending desktop input:

sh
zuse run examples/catalog.zuse
zuse check examples/validate-api.zuse

The validation fixture intentionally contains a placeholder window ID and an example node path. Use check for that file. To verify an installed package, run the safe catalog example from the consuming project, or execute the inline catalog command in the installation section.

Publish a package#

A package consists of a zuse.json manifest and ordinary .zuse source files. This repository is a small example: the manifest names the package, its version, its entry module, and its public exports. A package author can use their own Git repository and publish a version tag; no central registry account is required.

After committing reviewed source and configuring that repository's origin, inspect and publish the current manifest version:

sh
zuse pkg publish --dry-run
zuse pkg publish
gh repo edit OWNER/REPO --add-topic zuse --add-topic zuse-package

Add the zuse and zuse-package GitHub topics so other users can discover the repository with gh search repos --topic zuse. The topics are discovery labels; consumers should inspect the manifest and source before choosing a package.

Use a new version for changed source. Consumers select a source revision with pkg add or pkg update and commit the resulting lockfile. See the Zuse package-management documentation for command behavior, dependency resolution, and the lockfile format.
