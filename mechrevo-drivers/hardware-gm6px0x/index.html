旷世 16 Pro GM6PX0X 本机验证

日期：2026-10-14；2026-10-15／16／17／18 续验（Asia/Taipei）。这是单台机器的部分功能验证，不是完整兼容认证。

2026-10-23 低速风扇配置调整#

本机运行内核 7.2.11-arch1-1、驱动包 4.24.0.r165.gfc48597-1 和 stock TCC 3.0.10-1；tuxedo_keyboard 运行与磁盘 srcversion 均为 5899CC006083121EA48734C。用户报告风扇偏慢，读取到狂暴模式下 CPU 约 61°C、 CPU 风扇约 1750 RPM、GPU 风扇约 3343 RPM。未复现驱动读取错误。 模式切换时的风扇重新初始化由用户测试触发；未开启采集时 D-Bus 速度 -1 是 TCC 的既有行为，均不作为故障依据。

办公配置已有 60% 最低转速，但游戏、狂暴与默认配置仍为 0%。本轮仅将这三个 现有配置的 minimumFanspeed 提到 60，保留其余字段、100% 上限和温度调速。 通过 SIGHUP 重读配置后，活动狂暴模式回读为 60；26 个约一秒间隔样本中 CPU 风扇为 2619–2782 RPM、GPU 为 3599–3855 RPM，CPU EC 温度为 59–60°C。 自然负载下的这段观察证明最低请求与转速发生变化，不证明满载散热、其他模式的 物理效果、重启保持或其他型号兼容。百分比请求也不等于固定机械转速。

源码中的办公、游戏、狂暴新建配置采用相同 60% 下限；同步逻辑仍保留已有用户 配置，不自动覆盖旧下限。已有安装需要单独调整其配置。原配置及采样保存在 ~/Backups/mechrevo-drivers/light/2026-10-23/fan-floor/，私有日志不提交。 未更换内核模块或 TCC 包，未发布 AUR。

2026-10-24 thermald 功耗抖动修复#

只读检查发现当前受管 thermald 配置在 x86_pkg_temp 达到 90°C 时，日志反复记录 rapl_controller 在 55W、48W、34W 和 27.5W 之间切换，随后在温度回落后立即回到 55W。该循环与 1 秒轮询和原先的零滞回一致，会把温度采样噪声变成可见的功耗／性能抖动； 它不是风扇 RPM 读错的证据。

源码把这个已限定在 GM6PX0X / N.1.09MRO07 的 90°C 软件控制点改为 3°C 滞回：降温动作 仍在 90°C 触发，需低于 87°C 才释放热限制。55W 上限、双 RAPL 接口、原生降温设备顺序 和硬件 TCC 均不变。离线功耗回归覆盖 124 项且通过。

本机随后备份旧状态，先用旧版工具清除原配置（两路 PL1 回到 140W），再安装固定源码 c60aee5e6ffe8ac46a57a7922112a79ae1b063df 构建的 mechrevo-power-control 0.1.0-19， 重新设置 55W + 90°C + 1 秒轮询。安装后的 thermald 日志解析到 hyst:3000，两路 PL1 回读均为 55W，服务 active，pacman -Qkk 为 22 项零改动。复核时 CPU package 约 83–85°C、CPU/GPU 风扇约 3575/4939 RPM；当时系统 load 约 26–29，属于背景负载观察， 不能当作满载性能、长期稳定性或完整散热验收。恢复材料在 ~/Backups/projects/mechrevo-drivers/light/thermal-hysteresis-20261024/。
