界面设计

机械革命控制中心使用 Rust / egui 原生界面，共用 Rust 核心处理设备状态与控制事务。布局在 desktop.rs，常用控制在 controls.rs，颜色与字体在 appearance.rs。功能范围见 PRODUCT.md。

信息与视觉层次#

首页按使用顺序展示温度与风扇、性能档位、电池保养与屏幕亮度、常用设备控制、设备详情。实时读数和常用操作优先占用空间；数据来源、接口能力与回读说明按需展开。桌面布局的验收目标是在 1280×900 默认窗口中，同时看到五档性能选择、当前运行状态、预览入口、电池保养和屏幕亮度。

界面用石墨黑、暖白和少量暖沙色建立层次。面板通过背景明度、对齐与间距分组；侧栏使用浅层背景标出当前页面。常规面板、导航和档位按钮均无装饰描边，侧栏与正文之间用留白分隔。键盘焦点仍有明确轮廓，错误、忙碌和操作结果保留对应文字。

语义颜色 深色主题 浅色主题
页面背景 #0D0D10 #F7F7F5
面板背景 #17171B #FFFFFE
正文 #F1F1F4 #1E1E20
强调色 #EACFAB #744D26

CPU 读数与曲线采用正文色，GPU 采用琥珀色，并各自保留名称和单位。选中项使用暖色背景与文字共同表达状态。两套主题分别定义正文、次要文字、强调、警告和错误颜色；颜色回归将文字对比度 4.5:1 作为检查门槛。

Manrope 用于拉丁文字和品牌，中文由系统字体补全，运行时不下载字体。温度与风扇读数使用 egui 等宽字体，让相同位数的数值和单位保持位置稳定。背景保持纯色，面板没有纹理或阴影。

布局与响应式行为#

布局按实际内容确定高度，保留读数和操作空间。常规面板圆角为 12，标准／紧凑模式内边距为 20／16；面板可用宽度不足 380 时分别降为 16／12。性能区使用开放布局，标题、当前运行档位和选择项直接排列，避免再嵌套一层面板。

性能按钮的列数由区内可用宽度决定：至少 720 时显示五列，480–719 显示三列，300–479 显示两列，更窄时显示一列。按钮最低高度为标准 68、紧凑 60，较长文字可以继续撑高。当前回读档位与待选择目标分别呈现，选项名称和用途保留为辅助技术可读的标签。

温度与风扇区域随真实内容自然增长。宽度达到 680 时，CPU／GPU 读数和对应风扇位于左侧，趋势位于右侧；窄窗改为上下排列。趋势绘图区高 104，区域整体还包含名称、当前值与采样时间。额外传感器、大字体和换行可以增加整体高度，不裁切内容来维持固定卡片尺寸。

  • 默认窗口为 1280×900，最小为 360×280，均为逻辑单位。
  • 可用宽度至少 1060 且高度至少 440 时显示 184 宽侧栏；其余尺寸使用可换行的顶部导航。
  • 导航固定在正文滚动区之外。正文宽度不足 480 时，刷新、自动采样和显示设置移入滚动区，为内容保留可操作空间。
  • 电池／电源与亮度在足够宽的正文中并列，在窄窗中上下排列；所有页面维持纵向滚动，长来源路径允许换行。
  • 概览、控制、传感器、型号目录共用导航和设置。长设备名在标题区省略，悬停和设备详情保留全名；模拟数据始终有明确标识。

数据与控制#

CPU／GPU 显示同类当前最高的有效温度，曲线显示对应实际来源的历史。历史按机器身份和传感器来源隔离，每个来源最多 120 点；缺失读数形成断点，重新绘制界面不会新增采样。至少三次有效采样才绘制曲线，横轴使用采样时间。明确标注 CPU 或 GPU 的风扇归入对应组，通用风扇编号独立显示。

自动采样默认开启。启动时只读刷新，此后距上次快照至少 3 秒且后台空闲时更新；待确认预览期间暂停。关闭后显示“手动更新”。界面重绘与硬件采样分别调度，动画设置只控制视觉过渡。

控制入口来自运行时枚举的接口。性能档位、电池、键盘和屏幕亮度都经过选择、预览、显式应用与回读。选择只修改请求目标，当前状态继续显示设备回读值；不可用项显示具体原因。型号目录展示产品资料，实际可控范围由后端能力结果决定，见 OEM 功能覆盖。

共享实现与 Project Z#

CLI 使用 Project Z 的 zclap = 0.1.4 解析命令。RGB 十六进制处理集中在核心的 color.rs，复用 zhex = 0.1.3。GUI 的 RGB 文本调用 mechrevo_console_core::color::format_rgb_hex，与其他前端共用格式规则。

GUI 的窗口、布局、绘制和输入继续由 egui / eframe 提供，设备能力与事务继续走共用核心。依赖版本见各 crate 的 Cargo.toml 与工作区 Cargo.lock；共享能力的接入位置与界面框架分别记录。

事务与偏好#

启动和读取状态使用普通用户权限。需要授权的操作在显式应用后请求授权，后台重新核对接口、目标范围、绑定与原值。切换目标或手动刷新会作废旧计划，每份计划只使用一次。

写入、回读或必要恢复尚未结束时，窗口保持打开并显示进度。失败时保留原始错误和回读／恢复结果；状态未知时继续阻止后续写入与关闭，不自动重放操作。界面通过单个后台任务执行设备调用，重复刷新不堆积任务。

主题、80–160% 文字缩放、标准／紧凑显示、自动采样和动画偏好保存在 eframe 用户配置目录。操作计划与温度历史只保留在当前进程中。

验收依据#

布局回归覆盖深浅主题、窄窗、大字体、DPI、长文本、键盘导航、底部可达性、未知读数及预览／应用隔离。完整桌面场景同时提供五档性能、充电、屏幕亮度、CPU／GPU 温度和双风扇数据，检查首屏入口与同排档位，并通过真实点击验证请求目标和当前值仍分别保存。

软件渲染图用于检查 egui 内容，原生窗口截图用于核对实际窗口、字体与交互。截图流程见 视觉验收。模拟数据只用于独立预览和测试；硬件写入、实体灯光、噪声以及各平台兼容性分别记录实机结果。本设计文档说明实现约定与检查范围，具体执行结果以对应验收记录为准。
