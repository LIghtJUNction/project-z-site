Click compatibility

The fixed target is Click 8.5.1, released 2026-11-06, at commit cf19179e8e2fd54c601378cec9e0d21bb12b6fb1. The target was verified on 2026-11-11 against PyPI and the upstream Git tag.

The contract covers public object names, call parameters and defaults, return annotations, class members, properties, deprecated imports, exception behavior, CLI output and terminal tools. The generated API inventory records each declaration and associated upstream test source. The .pyi declarations describe this same fixed target.

Unfinished compatibility#

Full Click compatibility is not yet complete: 1 known item remains unfinished. Passing the pinned upstream suite is evidence for that suite, not proof of identical behavior in every interpreter configuration. The release gate blocks stable versions while this list contains unfinished items; an explicitly disclosed prerelease can be published only after the existing test, API, Shell and safety gates pass.

Item Click target zclick behavior Status
Import and command invocation in Python subinterpreters Click 8.5.1 imports and invokes commands in CPython 3.12 isolated and shared-GIL subinterpreters after initialization in the main interpreter. zclick requires the main interpreter. Its native module rejects initialization in subinterpreters with ImportError. UNFINISHED

The machine-readable known gap list includes the cause, reproduction command and pinned upstream sources. scripts/check_subinterpreters.py records the Click/zclick difference separately from safe rejection: compatibility_passed remains false even when safe_rejection passes. It checks isolated and shared-GIL configurations, both import orders, and successful use of the main interpreter afterward. No upstream test has been removed, weakened or marked xfail for this limitation.

These local numbers record development snapshots. The detailed reports retain test IDs and source hashes; they do not assert that every later code change is already validated. The release gate requires fresh reports for the exact immutable release commit, all 33,459 pinned test IDs, the public API audit and real execution of all four Shell runtimes. The final release includes the complete evidence archive and raw performance measurements.

The normal run preserves the upstream not stress development selection. The release workflow runs all four original stress functions with their original parameter counts, then checks the union of test IDs. It rejects failures, collection errors, missing tests and extra skips. Upstream platform skips and expected failures retain their original conditions; they are reported separately.

Tests are copied only into .cache/click-migrated, outside the runtime package. The migration changes package imports, module references, monkeypatch import paths, subprocess imports, distribution metadata lookup and four module-qualified object repr patterns. The complete edit log is .cache/click-migrated/namespace-migration.json. Assertions, argument values, expected behavior and skip markers remain intact.

Before Python 3.12, f-strings are opaque tokenizer strings. The migrator uses AST source positions to rename only package-name expressions inside them, retaining literal output text. Test ID canonicalization also normalizes the three upstream program-name cases built with platform path separators and five exact Enum parameter display IDs whose names differ on Python 3.10. The latter map only complete IDs in the pinned test_choice_default_rendering test; distinct defaults remain distinct, and duplicate canonical IDs within one report are rejected. Test arguments and assertions are unchanged. The fixed count and ID fingerprint are recorded in test-manifest.json.

Migration and dynamic behavior#

Use import zclick as click and replace from click.module with from zclick.module. The distribution installs only the zclick namespace and never rewrites sys.modules['click']. An extension that internally imports original Click still uses original Click: module aliasing does not merge class identities across packages. Such extensions need their own import migration and tests.

Command callbacks, parameter objects and type converters remain Python extension points. Invocation observes changes to command.params, registered commands, callbacks and option attributes. Per-invocation defaults, environment values and context state are not cached. The native parser validates the current definition before reusing its most recent immutable, owned Rust schema; it does not retain borrowed schema references or Python application objects. Warmed-command pickle/deepcopy, alias and arity mutation, method replacement, reentry and original argument identity have explicit regressions.

The target's own help-option cache is preserved: after its first creation, later nonempty help-name settings reuse that object, while empty help names disable it for that context. Without an automatic help option, get_params returns the existing parameter container. Help-name hashing, parameter reads, duplicate-name comparisons and debug-only warnings follow the target's order. Paired Click/zclick cases in test_command_help_protocols.py check these container, cache and warning behaviors. Parser action attribute reads and equality comparisons are paired in test_native_actions.py.

CliRunner temporarily changes interpreter-wide streams, environment and working directory, matching Click's isolation model. Concurrent runner invocations in the same process are not a supported thread-safe isolation boundary. Native parsing state is per call; this does not make the testing tools thread-safe.

zclap adaptation#

zclap contract Click requirement Adaptation
Runtime definitions are borrowed Python can create and mutate parameter tables Retain an owned, immutable Rust schema; verify current definitions before reuse and borrow its data during parsing; no leaked strings or fake static lifetimes
Option names and values have kernel conventions Multiple prefixes, aliases, combined shorts, negative and dash-prefixed values Translate current option spellings and use zclap event parsing for recognition; retain original values and error spelling
Parent/child parsing scope and final validation differ Click controls interspersed arguments, chain groups and deferred validation A Rust semantic layer controls boundaries and event sequencing around zclap
Kernel help output has its own layout Exact Click help and terminal formatting Rust wrapping/ANSI primitives feed the Click-compatible formatter
Kernel arity rules are lower-level Variadics, optional values, callbacks and source precedence Rust semantic operations and Python extension hooks preserve target ordering

The core directly depends only on registry zclap = 0.1.4 and builds with no_std + alloc. The Python extension also depends on PyO3, uses std, creates Python objects and allocates memory. The published Python package has no third-party Python runtime requirements. Click, pytest, Maturin and type-checking tools are development dependencies.

The binding supports the main Python interpreter, including its worker threads. Subinterpreter imports are rejected before initializing PyO3's Python-object caches. This is an explicit compatibility limit, not a claim of subinterpreter support.
