zclick

基于 zclap 的 Click 参数语义与 Python 预览绑定。

Python command-line interfaces backed by Rust and zclap. Import the public API as import zclick as click, including the matching zclick.core, zclick.types, zclick.testing and zclick.shell_completion submodules.

The fixed compatibility target is Click 8.5.1, source commit cf19179. The versioned documentation, API inventory and original tests are pinned in compatibility/target.json. The implementation uses registry zclap 0.1.4, PyO3 0.30.1 and Rust 1.99.1 / Edition 2024.

This is a preview release; the complete compatibility target is not yet met. CPython subinterpreters are currently unsupported and are explicitly rejected at native module initialization. The locked PyO3 binding has Python object caches that are not partitioned by interpreter. See the open compatibility record. Stable publication is blocked while an open compatibility gap remains.

Installation and a first command#

The 0.1.1a3 preview is available on PyPI and GitHub Releases. Install the published version:

sh
python -m pip install --upgrade zclick==0.1.1a3

To select the latest available preview instead:

sh
pip install --pre zclick

The publication verification records all 12 wheels and the source archive, matching PyPI/GitHub hashes, the Trusted Publisher identity, and a new isolated PyPI installation that ran the prompting greeting example without original Click. Earlier a2 and a1 verification records remain available.

Source installation requires Rust 1.99.1 and the platform build tools.

Ordinary CPython wheels support Python 3.10 and newer; PyPy and free-threaded CPython require their corresponding wheels or an interpreter-specific source build. The intended stable installation is pip install zclick once the outstanding compatibility gate is satisfied.

python
import zclick as click

@click.command()
@click.option("--count", default=1, type=int, help="Number of greetings.")
@click.option("--name", prompt="Your name", help="The person to greet.")
def hello(count, name):
    for _ in range(count):
        click.echo(f"Hello, {name}!")

if __name__ == "__main__":
    hello()

Migration#

Replace import click with import zclick as click. Replace submodule imports, for example from click.testing import CliRunner, with from zclick.testing import CliRunner.

The wheel installs the zclick namespace. It has no third-party Python runtime requirements, does not install a top-level click package, and does not redirect another package's imports. Original Click is only a development and comparison dependency.

A third-party extension that imports Click internally continues to use Click. Its classes and context stack require separate migration. The extension compatibility report reproduces this boundary with locked releases of click-didyoumean, click-plugins and click-repl, including their original-Click control runs. Changing an application's import alias does not automatically migrate those extensions.

Compatibility and performance#

The release gate requires the complete 33,459-case official test collection, including 31,000 stress cases, with the same test IDs and original platform skip/expected-failure conditions. It additionally checks 196 public objects and their members, the 12 upstream typing examples, native property and differential tests, and real Bash, Zsh, Fish and PowerShell completion. Results are tied to an immutable implementation commit; configured platforms are not reported as passing until their jobs succeed. See COMPATIBILITY.md and the CI runs.

Version 0.1.1a3 completed the full release validation at source 9afcc753. All 61 jobs in the release run succeeded. The validation record separates the 12 normal test environments, seven stress environments, API and Shell checks from the 12 actual wheel installations and source-archive rebuild. Original skips and the unresolved subinterpreter difference remain explicit. The a2 validation record is retained.

The 0.1.1a3 performance report compares fixed Click 8.5.1, the published a2 wheel and a3 in twelve balanced rounds on each of two Linux hosts. Local CPython 3.12.14 and release-CI CPython 3.14.10 both ran on machines reporting AMD EPYC 9V74; their systems, available CPU counts and wheel build environments differ. Ratios divide the reference median wall time by a3's: above one means lower a3 latency. The last two columns isolate the comparison with the previous release from the project's advantage over Click.

One-option parsing improved relative to a2 by 1.615× locally and 1.674× in CI. Nested invocation improved by 1.166× and 1.143×. Full invocation at 1,000 options was 1.776× and 2.128× relative to Click, but its new improvement over a2 was only 1.042× and 1.033×. The large wrapping advantage over Click also predates this release; wrapping regressed slightly relative to a2 in both runs.

Pure parsing still has slower cases: one and ten options locally, and ten and 100 options in CI. The 100-option local advantage did not reproduce in CI. One-option help regressed relative to a2 on both hosts, and ten-option help regressed in CI; both CI help cases were slower than a2 in all twelve paired rounds. These results do not support a universal speedup.

All eight fresh-process medians were lower than Click on both hosts, while four per host were higher than a2. Whole-worker peak RSS remained above Click: a3 / Click measured 25.193 / 24.062 MiB locally and 33.121 / 32.014 MiB in CI. Python allocation samples do not include every native allocation. All eighteen warm workloads, eight cold workloads, CPU times, variation, import and memory observations are retained in the report.

The CI benchmark and published GNU wheel contain the same 18 Python/native runtime files, although their wheel archive hashes differ. The earlier a2 and a1 reports remain unchanged historical measurements.

Examples#

Example Behavior
hello.py Decorators, options, prompting and output

sh
python examples/hello.py --count 2 --name Ada
python examples/pipeline.py --text 'hello world' uppercase replace WORLD Rust
python examples/workspace.py --prefix demo convert 0x10000000000000000

Shell completion setup covers the source/complete protocols and the scope of actual shell-engine validation.

Development#

Use Python 3.10 or newer and the pinned Rust toolchain. Create a virtual environment, install Maturin and the test dependencies, then build the extension:

sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
maturin develop --release --locked
python -m pytest tests
python scripts/run_compatibility.py

Use the development guide for complete stress verification, cross-platform builds, dependency audits, reproducible benchmarks and version bumps. The release workflow builds and installs the actual wheels before publishing them.

Architecture#

Python objects preserve decorators, custom subclasses, callbacks and ordinary Python values. The native extension validates current definitions before reusing an immutable parsing schema; every call has its own execution state. The Rust core performs token recognition through zclap, applies Click argument consumption rules, schedules parameters and formats text. Rust also drives command groups and parser actions through Python's current methods. The core uses no_std with alloc; its only direct third-party dependency is zclap. The extension uses PyO3 and the Rust standard library.

The Python interface accepts mutations between invocations. Each parser or command retains at most its most recent owned Rust schema. Defaults, environment values, callbacks and contexts are evaluated anew. User callbacks run without a native lock or borrowed mutable parser state. Python integer conversion uses Python integers rather than fixed-width Rust integers. Input strings preserve surrogate code points at the binding boundary.

CliRunner changes interpreter streams, environment variables and sometimes the working directory. Use separate processes for concurrent runner tests.

The project implementation is MIT licensed. Distribution notices for the generated Click API declarations, Rust dependencies and standard library are listed in THIRD_PARTY_LICENSES.md.

Rust crate#

The independent zclick-core library is distributed through crates.io. It provides the no_std + alloc argument and terminal-text kernel over zclap; Python command objects and interpreter bindings remain in the Python package. See the Rust crate README for installation, API scope, and the locally validated scripts/publish_core.py publication command.
