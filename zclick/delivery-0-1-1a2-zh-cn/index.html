zclick 0.1.1a2 交付记录

本轮结论与发布状态#

本轮完成了可复用的 Rust 解析结构、参数输入借用、受条件约束的原生排序，以及 Python 类型选择、帮助和终端格式化路径的优化。两台主机上，1,000 个选项的重复解析相对已发布 0.1.1a1 分别为 2.535× / 2.354×，完整调用相对 Click 8.5.1 分别为 1.771× / 2.017×。完整调用对旧版的改善只有 1.042× / 1.050×，不能称为这一版本的大幅新增收益。下文的两个数依次表示本地与发布 CI 测量。完整性能记录

纯解析对 Click 的优势没有跨主机复现。 1,000 个选项在本地测得 1.236×，CI 则为 0.975×；CI 中 a2 的中位耗时略高。两组数据均保留，不能只选本地较好的结果。

0.1.1a2 已发布到 GitHub Releases 和 PyPI。 Release 43052475382 的 61 个任务全部成功，标签 v0.1.1a2 指向源码 7e3d597873b737bbfc8c2df090773aad56d9bd73。公开 PyPI 的 12 个 wheel 与一个源码包，SHA-256 均与实际下载核对的 GitHub 制品一致；也已在仓库外的隔离环境从 PyPI 安装并运行示例。发布核验

0.1.1a2 仍是预发布，完整 Click 兼容目标尚未达成。 CPython 子解释器兼容继续记为 UNFINISHED。小规模重复解析、单选项完整调用和嵌套命令在两台主机上仍慢于 Click，因此没有“所有 Click 应用都大幅提速”的结论。兼容性清单、未完成项

优化实际减少了什么工作#

复用结构，保留每次调用的状态#

解析 schema 是选项名字和参数消费规则的结构表。一个命令或解析器最多保留最近一份由 Rust 拥有的不可变 schema；每次调用先读取当前定义并核验，匹配时复用，变化时建立新表。这样，未变化的名字和查找表不必反复构造。核验本身仍在计时范围内。实现、结构变更测试

默认值函数的结果、环境变量、提示输入、Context 和回调结果不进入这个缓存。修改参数、别名、参数个数、callback 或类型方法后，后续调用仍读取当前 Python 对象。重入拥有独立解析状态，已经执行过的命令也有 pickle 和 deepcopy 回归。动态语义、复用命令测试

减少输入复制和解释层的重复操作#

普通参数字符串在一次原生调用期间借用解释器提供的 UTF-8 缓冲区，并保留原 Python 对象的所有权。参数来源通过索引记录，避免把相同内容或空缓冲区误当成同一个对象。含 surrogate 的字符串走可逆表示；这条路径和结果对象的创建仍可能分配内存。边界测试

Python 适配层减少了临时类型映射表、重复导入和部分格式化辅助对象。内置类型选择每次读取当前公开类型对象；字符串子类、自定义转换器和被替换的方法仍可被观察到。单行帮助的常见情况避免提前加载 inspect，特殊空白继续使用当前解释器的标准库语义，包括 Python 3.12 与 3.13 的差异。表面接口回归

大参数表预建位置索引，再稳定排序#

普通 CPython 对象、实际的 list 容器和至少 512 项声明参数满足守卫条件时，原生排序先建立首次出现位置的查找表，再做稳定排序。它减少了重复 list.index 线性查找，排序本身最坏仍需 O(n log n) 时间。小列表、自定义相等比较、属性或真值协议，以及 PyPy，继续执行 Python 的实际 sorted 和 index 规则。排序实现、排序回归

以上工作仍使用 zclap 做实际选项识别和最终验证。类型转换、参数回调等 Python 扩展点保留当前方法调用。完整执行时间还包括启动、导入、命令构造、上下文、转换、用户回调和输出，因此重复解析的加速比不能直接当作整个应用的加速比。架构说明

测量方法与能够支持的结论#

每次三方比较使用同一 Python 解释器，wheel 分别安装到独立环境。每轮使用新的隔离进程，每台主机各 12 轮；每六轮包含三方的全部六种先后顺序一次，冷启动各场景另有独立顺序。输出、解析结果和对象身份先检查再计时，原始报告保留 wheel、源码、Cargo.lock、主机和每轮观测。正常 GC 保持启用。测量协议

大规模重复解析相对旧版的改进在两台主机的每轮配对中都出现，但完整调用只有小幅新增改善。本地 1,000 选项完整调用的 a1/a2 配对比值为 0.861–1.424，CI 为 1.034–1.075。CI 的 1,000 选项纯解析相对 Click 的配对比值为 0.938–1.065，跨越 1。冷启动也有离群值：本地 a2 的 100 选项帮助中位数为 33.707 ms，最大值为 149.031 ms，变异系数为 78.43%。CI 波动较小不能成为删除本地离群值的理由，全部样本保留。

本地旧版是发布的 manylinux_2_17 wheel，候选是本机构建的 manylinux_2_34 wheel。解释器、测量主机和顺序得到控制，构建环境仍不同，不能把全部变化归因于源码。CPU 频率没有锁定，也没有可用的频率读数；共享主机调度和文件缓存仍会影响结果。CI 使用与正式分发对齐的 manylinux 构建，运行时内容也已逐文件核对；它独立补充了证据，没有替换本地结果。跨主机的变化同时涉及 Python 版本与处理器，仍不能单独归因。

内存指标也没有“全面降低”的结论。整个 worker 的 RSS 中位数，本地 a2 / Click / a1 为 25.492 / 24.059 / 25.107 MiB，CI 为 33.324 / 32.039 / 33.287 MiB。它包含导入、哈希校验、tracemalloc 和整组工作负载。1,000 选项解析的 Python 分配峰值，本地从 a1 的 163,850 字节降到 a2 的 54,281 字节，CI 从 175,010 字节降到 54,355 字节。Python 分配指标不覆盖所有 Rust 分配，不能替代整个进程的内存测量。

验证方法与兼容边界#

发布门禁仍要求固定的 33,459 个官方用例 ID，其中 31,000 个为压力用例，以及 196 项公开 API及成员契约、12 个官方 typing 文件和四种真实 Shell 执行。用例、断言和原版 skip/xfail 条件保持不变，逐例报告要与不可变源码提交绑定。分片只改变执行批次；平台跳过项不能计作实际通过。固定库存、完整门禁说明

本轮新增回归针对结构复用、方法和实例修改、重入、复制、字符串身份、Unicode 空白，以及排序中的相等比较和首次位置规则。大命令的部分动态边界在独立解释器中验证，避免前一个测试改变优化适用条件、掩盖后一个测试。本次发布的 12 个普通兼容测试任务与 28 个压力测试任务均已成功完成，原版 skip/xfail 仍单独记录；逐环境计数见发布验证记录。

12 个 wheel 和一个源码包的实际安装执行检查均成功。 源码包先重新构建，再安装运行。每个制品的实际 runner、解释器和系统记录在证据中；wheel 的最低系统兼容标签不等于在那个最低系统版本上运行了全量测试。

仍需明确保留以下边界：

  • 子解释器尚不兼容。 当前绑定在初始化早期拒绝子解释器导入，避免跨解释器错误共享 Python 对象；安全拒绝不等于实现了 Click 的行为。
  • 第三方扩展的内部导入仍需迁移。 应用里的 import zclick as click 不会改写扩展文件中的 import click。扩展实测单独记录了三个原版扩展的类身份和上下文边界。
  • CliRunner 不提供同进程线程间的隔离保证。 它会替换流、环境变量和工作目录；并行 runner 测试使用独立进程。free-threaded wheel 不改变这一工具边界。
  • 安装检查与完整平台测试范围不同。 wheel 成功构建和安装执行，不能自动证明该架构运行了全部官方用例。Shell source 执行、终端编辑器注册记录和真实终端设备也需区分，具体范围见补全文档。

复现入口#

以下为普通 CPython/Linux 开发环境示例。Windows 的环境激活方式不同；PyPy 和 free-threaded CPython 构建需要增加 --no-default-features。完整跨平台步骤见开发指南。
