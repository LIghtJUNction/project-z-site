Translations

English README · 中文 README

Runtime contract#

LMM translates terminal presentation while keeping machine-readable output independent of the selected language. Both catalogs are compiled into the binary using include_str!; language selection does not require a network request, a working-directory lookup or another runtime dependency. The implementation is in src/i18n.rs, with subprocess coverage in tests/i18n.rs.

File Purpose
locales/en.json Complete English catalog and canonical machine prose
locales/zh-CN.json Complete Simplified Chinese catalog
src/i18n.rs Locale selection, typed messages and named placeholders
scripts/check-i18n.py Catalog values, references and placeholder validation
scripts/test_i18n_checks.py Validator regressions using temporary fixtures

Select a language#

The global --lang en or --lang zh-CN flag works before or after a subcommand. Selection happens before Clap builds help. An unsupported explicit language is an argument error and does not run the requested command.

Without the flag, the first nonempty value in LMM_LANG, LC_ALL, LC_MESSAGES and LANG selects the language. Unknown values, C and POSIX fall back to English. Supported Simplified Chinese aliases include zh, zh_CN.UTF-8, zh-SG and zh-Hans; Traditional Chinese does not yet have a catalog and falls back to English. A value after -- is positional data and cannot select a language.

The selected locale is immutable for the CLI process, including the OAuth callback thread. An uninitialized library defaults to English. Library callers can use Locale::ZhCn.text(key) or msg(key).render_in(locale, values) without mutating global state; tests use explicit locales and child-process environments.

Add or change a message#

Use the same semantic key in both catalogs and keep a complete sentence together. For example:

json
{
  "output.target": "{software}: installation {installation}"
}
rust
msg("error.unknown_software")
msg("output.scope").render(&[("time", &checked_at.to_string())])
text("arg.instance")

Named placeholders may move within a sentence, but their names and occurrence counts must match. Formatting specifiers, conversions, nested templates and literal braces are not supported. Substitution happens once: inserted values are never parsed as templates. Escape untrusted paths and server text with debug formatting, such as format!("{value:?}"), before inserting them into terminal output.

help.template belongs to Clap rather than the message renderer. Preserve Clap's named fields. Command descriptions and help headings are translated; Clap's own argument validation details and built-in annotations remain in upstream English.

Keep JSON and adapter errors stable#

Message serializes its English text regardless of display locale. JSON keys, descriptions, purposes, notes, blockers, recognized error text, command names, IDs, protocol values, currencies, numbers and timestamps do not change when only --lang changes. Catalog and provider search can match both bundled languages without changing returned identifiers. Original vendor metadata is preserved rather than translated.

Existing native adapter APIs return strings or typed errors that are also used in JSON previews. They use english(key) to retain a canonical value. At the terminal boundary, message_from_english recognizes only exact catalog values and recovers a typed message; localize translates that recognized value. Unknown external text stays literal. Do not perform broad string replacement or interpret an adapter's text as a template.

Recognized CLI and OAuth errors include a stable error_code; unclassified adapter strings have no recognized code. Consumers should inspect structured outcomes and known codes instead of matching human prose. The hidden credential command is a raw-token pipe and rejects JSON or terminal token output in either language; it is not a general-purpose account display command.

A missing localized entry falls back to English and then to its visible key. This avoids a runtime failure but does not make an incomplete catalog acceptable: repository validation requires matching nonempty catalogs and rejects missing or unused message references.

Verify a change#

Run these commands from the repository root:

sh
python3 scripts/check-i18n.py
python3 scripts/test_i18n_checks.py
mise exec -- cargo fmt --all -- --check
mise exec -- cargo test --locked
mise exec -- cargo clippy --locked --all-targets --all-features -- -D warnings
mise exec -- cargo package --list --locked

The Python checker rejects duplicate and malformed keys, empty or non-string values, disallowed control characters, CJK text in the English catalog or Rust sources, mismatched placeholders, and missing or unused references. It recognizes msg, text, english and the typed enum message mappings. Its fixture tests do not compile Rust; the Cargo tests verify locale precedence, help, errors, JSON equality, native adapter refusal paths and escaped untrusted paths.

The source package must include both catalogs, both READMEs and the translation guide. To add another language, extend Locale, its aliases, its embedded catalog mapping and Locale::ALL, then add subprocess tests and update documentation in the same change. No command, adapter permission or credential-store behavior should change as a side effect of translation work.
