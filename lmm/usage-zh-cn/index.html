使用指南

中文 README · English

LMM = Language Model Mesh，中文「语言模型网络」。本指南说明当前源码中的命令及其实际边界。

这是 TokenNotIncluded/lmm 独立维护的 Rust CLI。crates.io 包名为 lmm-cli，可执行文件名为 lmm；父仓库通过子模块锁定版本，CLI 的构建和依赖独立管理。

当前是开发预览，已实现服务商预设、桌面 OAuth、模型目录与余额读取、限定版本的 Pi Provider 适配器，以及 CC Switch 的 Linux 受管发行包生命周期。 Pi 使用显式指定的官方 Pi 1.2.0 SDK 安装和恢复固定 Provider，授权与激活仍在 Pi 内完成。 CC Switch 支持固定官方 AppImage 的安装、更新、按回执恢复、卸载、显式启动和 schema 24 的只读检查；独立应用授权、仅添加配置、目录同步和撤销分别使用其管理合同。 原生应用激活与真实调用需要单独验收，其他软件的写入流程继续明确阻塞。详细边界见 受管发行包说明 和 原生凭据接入说明。

完整产品要求见 原始需求。完整需求保留为目标，不因当前实现范围而缩减。 与 Magpie 的功能对照及下一步任务见 Magpie 对照。实现使用 Rust，不包装或启动 Magpie，也不依赖 Go 运行时。

构建当前源码#

从独立仓库根目录使用固定工具链构建：

sh
mise install
mise exec -- cargo install --path . --locked
lmm --lang zh-CN --help

mise.toml 固定 Rust 1.100.0，Cargo 清单最低版本为 Rust 1.99.1。构建需要本机编译工具；Linux OAuth 另需运行中的 Secret Service，Windows/macOS 使用系统凭据库。已发布包可能不包含当前源码能力；这里不把源码验证作为某个已发布版本的验收。

语言选择#

--lang en 或 --lang zh-CN 可放在子命令前后，且作用于帮助输出。优先级为显式参数，然后是 LMM_LANG、LC_ALL、LC_MESSAGES、LANG 中首个非空值，最后回退英文。未知环境语言回退英文，不支持的显式参数会被拒绝。

终端帮助、提示和已识别错误随语言切换；JSON 中由 CLI 生成的说明、用途、提示、错误正文保持英文，字段名、状态值、标识符和数字不变。上游原始元数据保持原样。详见翻译指南。

当前可用#

  • lmm presets [关键词] [--json]：查询 56 项内置服务商预设，离线运行，不读取密钥、不访问服务商。
  • lmm catalog [关键词]：搜索明确项目身份的软件目录，分别说明安装、接入、维护能力。
  • lmm status [软件]：当前环境与 PATH 线索；指定 CC Switch 时校验受管发行包，显式 --instance 时读取 schema 24 的非凭据元数据；Pi 支持下文限定的显式设置检查。
  • lmm install|update|uninstall cc-switch --dry-run --json：可执行的固定发行包计划；确认时带原 --yes --plan-id。
  • lmm restore cc-switch --change <change_id> --dry-run --json：按回执恢复受管版本，保留后续修改和应用数据。
  • lmm run cc-switch：启动已校验的受管程序；启动成功不代表应用健康或模型调用通过。
  • lmm doctor [软件] --report：只读诊断摘要，移除实例和文件路径，仅输出各适配器允许的状态字段。
  • lmm setup [软件] --dry-run：生成带阻塞原因的预览；无目标且有终端时可选择软件。
  • --json：结构化结果；自动禁用交互。--non-interactive 同样禁止等待输入。
  • lmm login：桌面浏览器 PKCE 登录；凭据保存于系统凭据库。
  • lmm models [--json]：获取当前授权模型、服务器上下文/能力元数据、缓存价格及分组/信任倍率；未知保留 null，价格已含倍率，不调用模型、不切换配置。
  • lmm balance [--json]：读取余额 V2，保留服务端整数积分及美元单位；未知单位或失败不会显示为零。
  • lmm logout：撤销当前 issuer 下的 CLI 令牌族，成功后删除本地凭据；不影响 Pi/DSH 等其他应用。

Pi Provider 适配器（Linux / Pi 1.2.0）#

此适配器连接已经安装的官方 Pi 1.2.0 npm 包，仅管理明确项目内的 LMM Provider。 它不安装或卸载 Pi 本体，不复制 CLI 登录凭据。Pi 使用自己的 /login 授权、/model 选择和原生模型调用。 固定 Provider 来源为 git:github.com/TokenNotIncluded/pi-lmm-provider@f0c54764eb3d73e50790346f0dbab834587fe27b。

bash
lmm setup pi --add-only --instance /absolute/project --node /absolute/node \
  --pi-package /absolute/node_modules/@earendil-works/pi-coding-agent \
  --agent-dir /absolute/pi-agent --dry-run --json
# 核对预览后，用相同参数移除 --dry-run，并添加 --yes

setup / install 只添加固定 Provider；结果为 provider_added_authorization_pending，不代表模型已可用。 setup、sync、disconnect 的后续授权/目录刷新/撤销仍需目标 Pi 完成，因此实际执行返回 3 并报告具体阶段。 已有其他 LMM 安装来源时拒绝创建副本；默认服务商和模型保留当前选择。--activate 必须交由目标 Pi 的交互授权和模型选择完成。 update 只接受仍存在的自有固定来源，本版本不自动追逐最新版。 sync 验证 Provider 存在，明确返回 catalog_refresh_pending；在 Pi 中运行 /lmm-prices 才会刷新目录。 run pi 使用相同的四个显式路径启动 Pi，只允许交互终端。

restore / disconnect 加相同目标路径和 --yes，仅从原生设置事务中移除本次添加的精确来源。 这不会撤销 Pi OAuth 授权；需要撤销时在 Pi 中运行 /lmm-revoke。 用户后来新增的插件、默认模型及其他字段都会保留；若用户改写了此来源对象则拒绝恢复。 下载代码可能被其他实例引用，因此保留。uninstall 仍受阻，不删除 Pi 本体或未知资源。

无秘密日志在所选项目 .pi/lmm-owned.json，锁在 .pi/lmm-adapter.lock。 修改前持久化 pending，读回成功后才完成日志；中断或不确定结果保持待检查状态，不自动声称完成。 配置增删在 Pi 自己的 FileSettingsStorage.withLock 中读取最新内容执行，避免用旧插件数组覆盖并发编辑。 普通 CLI 的 OAuth 凭据继续只保存在系统凭据库；适配器从不读取 Pi 的凭据文件。

服务商预设#

bash
lmm presets
lmm presets deepseek --json

预设来自 Magpie 的固定版本，是服务商地址及相关元数据的静态目录。它不是已经配置的服务商列表，不代表当前账号有权限或额度，也不代表已完成服务商接入、模型发现或调用验证。端点和模型信息可能随服务商变化，不能作为实时承诺。

presets 查询服务商预设，catalog 查询软件目录，models 读取 LMM 账号的授权模型；三者分别表示不同内容。

登录与模型目录#

bash
lmm login
lmm models --json
lmm balance --json
lmm logout
# 自托管必须明确指定可信的 HTTPS origin，认证和只读命令使用同一 issuer
lmm login --issuer https://lmm.example.com --no-browser

服务端需要注册 lmm 客户端并启用已有 OAuth 服务。使用前应确认目标服务支持这些接口，并验证实际账号的浏览器登录流程。 CLI 只申请 catalog:read balance:read 和同意页显示的分组快照；没有 models:invoke、 MCP 或账号管理权限。CLI 登录成功不代表 AstrBot 或 CC Switch 已授权。

浏览器回调只监听 127.0.0.1 随机端口，等待默认 180 秒，可用 --timeout 10..600 调整。 --no-browser 仅关闭自动打开浏览器，不是设备码登录：浏览器仍须能访问本机回环端口。 无图形服务器跨设备授权尚未实现；非交互 login 直接返回，不暗中等待授权。 切换账号先 logout 再 login；已有 CLI 登录不会被新登录静默覆盖。

Windows 使用 Credential Manager，macOS 使用 Keychain，Linux 使用 Secret Service。 凭据库可能显示系统解锁提示；不可用时明确报错，不使用明文文件后备。 因此认证命令暂不支持 --non-interactive，会在访问凭据库之前退出；models --json、balance --json 只禁用 CLI 文本交互，系统仍可能要求解锁。 Linux 通过 zbus 访问 Secret Service，不再静态链接 libdbus； 运行时仍需要可用的 Secret Service；不能将开发机单测当作三个系统的实际凭据库验收。两项 Linux 原生凭据迁移测试需要显式提供隔离服务，普通 cargo test 会保留为 ignored。

认证操作使用当前用户状态目录中的无密钥 oauth.lock，防止并发登录/刷新/退出。 Linux 为 $XDG_STATE_HOME/lmm 或 ~/.local/state/lmm，macOS 为 ~/Library/Application Support/lmm，Windows 为 %LOCALAPPDATA%/lmm。 Unix 目录/锁文件新建权限分别为 0700/0600；已有不安全目录或锁文件会被拒绝。 刷新前将“不可重试”状态存入凭据库，响应丢失或保存失败后不会自动重放旧 refresh token。 此时需要退出再登录；退出撤销失败保留本地记录供重试，不能报告已完成。

模型目录只表示账号可见范围，不表示某个软件已经兼容。未知价格保留 null， 价格包含服务端返回的倍率，不重复计算；本命令不执行付费测试。

本地软件检查#

显式实例接受 AstrBot 部署根目录、CC Switch 配置根目录，以及下述 Pi 项目根目录：

bash
lmm status astrbot --instance /absolute/path/to/AstrBot
lmm status cc-switch --instance /absolute/path/to/.cc-switch
lmm doctor astrbot --instance /absolute/path/to/AstrBot --report --json
lmm setup astrbot --dry-run --json

Windows 使用当前 Windows 环境的绝对路径。AstrBot 只检查所选根目录的 data/cmd_config.json 路径；CC Switch 在显式 --instance 时打开只读 SQLite 事务，仅查询 schema 和非凭据的供应商元数据。 不自动搜索项目、其他用户、Docker 实例、局域网或远程机器。 PATH 文件可能是包装脚本或来自其他环境，因此只标为线索；不执行 --version。 符号链接和不可访问项显示 unknown，文件缺失只描述被检查的那个位置。

CC Switch 的受管安装与 schema 24 配置管理者依据本地日志和原生数据库确认；授权、实际模型及真实调用路径不凭这些事实推断。

Pi 的只读设置检查仅支持 Linux、声明为官方 Pi 1.2.0 的 npm 包格式，必须显式指定三个目录：

bash
lmm status pi --instance /absolute/project \
  --pi-package /absolute/node_modules/@earendil-works/pi-coding-agent \
  --agent-dir /absolute/pi-agent --json
lmm doctor pi --instance /absolute/project \
  --pi-package /absolute/node_modules/@earendil-works/pi-coding-agent \
  --agent-dir /absolute/pi-agent --report --json

这条路径只读包清单和所选 agent 的 settings.json、项目的 .pi/settings.json， 不需要 Node，不启动目标或 SDK，不读取 auth.json，也不创建状态目录或配置锁。 Linux 检查使用内核的禁止跟随符号链接标志逐级打开目录及设置文件。 pi_settings.provider_reference 区分固定来源、其他已知 LMM 来源和多个引用； 识别 Pi 1.2.0 常见的 npm 和 Git 来源写法，不解析本地插件路径、npm 别名或未知写法。 仅有无法识别的来源时结果为 unknown；已知 LMM 来源与无法识别的来源并存时为 known_with_unresolved_sources，并仍报告已知引用。即使为 no_known_source， 也不能据此排除其他扩展加载了 LMM。包引用不代表代码已安装或已加载。 lmm_added=referenced_in_settings 与 lmm_enabled=selected_in_settings 分别表示 引用存在和默认服务商字段为 LMM；二者不等同于运行时添加或启用。 项目的默认服务商、模型字段分别覆盖全局字段，provider_scope / model_scope 指出各自来源。模型只显示已设置/未设置，其他服务商只显示 other，不输出原始配置值。 多个已知来源会单独标出，不自动去重或修复。

未知版本、无法访问、符号链接（含目录祖先）、超过 1 MiB 的文件及已知字段结构不符， 保留 unknown 并使 status 返回 3；不存在的设置文件按未设置处理，不创建它们。 设置是分别读取的快照，不是跨文件原子快照；硬链接、绑定挂载以及文件打开后的并发修改 不在符号链接防护范围内。项目信任、启动参数、会话选择及模型缓存 可能改变实际行为，本检查不确认它们，也不验证 SDK 内容真实性、安装管理者或配置管理归属。 仅提供项目路径、未提供 Pi 格式检查参数时，仍保留原有路径检查行为。

软件目录中的完整兼容版本/平台/场景列表仍为空；上述局部配置检查不是完整接入兼容声明。 授权、连通性、实际服务商/模型及真实调用路径仍未验证。 status 的退出码 0 只表示完成对应只读查询，不能用于判断“软件可使用”。 doctor 即使配置检查通过也返回 3，--fix 仍阻止写入。 status、doctor、setup --dry-run 没有网络调用或付费验证。

--all 不把目录视为安装列表。update --all 仅包含已由 LMM 管理的 CC Switch；没有受管安装时返回阻塞。应用接入的 setup --all 仍无可执行目标。 --yes 不能消除能力缺失，不能代表支付、重新授权或切换服务商的同意。 单独 install 不要求登录。CC Switch 的写操作需确认精确计划，不能用 --yes 跳过计划 ID。

CC Switch 原生应用配置#

CC Switch 的应用授权与 CLI 只读登录分开。authorize 在浏览器中确认独立实例、授权分组与消费范围；凭据留在系统凭据库，配置使用 Codex 原生凭据命令获取模型 bearer，不复制 CLI token 或其他应用凭据。服务端必须支持相应独立授权和可恢复续期合同。

setup cc-switch --add-only 在显式实例的 schema 24 数据库中添加 LMM，sync 根据该应用的授权目录更新元数据并保留原模型选择。计划与执行需要精确目标和计划 ID；未知提交结果必须先用 receipt 查询原 change_id，不能新建操作重复执行。restore --configuration --change 按原生回执恢复受管理字段，后续编辑触发冲突。

数据库记录存在不等于本机 Codex 已使用该路由。--activate 和完整删除需要 CC Switch 的原生管理入口核对 live、代理与 Stack 状态；不能只凭 is_current 或数据库不活动标记完成激活或删除。credential 只供原生凭据管道使用，拒绝 JSON 和终端 token 输出。具体协议依据见原生接入证据。

开发#

从这个独立仓库的根目录执行，工具版本由 mise.toml 固定：

bash
mise install
mise exec -- cargo run --locked -- presets deepseek --json
mise exec -- cargo run --locked -- catalog
python3 scripts/check-i18n.py
python3 scripts/test_i18n_checks.py
mise exec -- cargo test --locked
mise exec -- cargo clippy --locked --all-targets --all-features -- -D warnings
mise exec -- cargo fmt --all -- --check
mise exec -- cargo build --locked --release

不需要先构建或启动父仓库中的核心、扩展或 Web 服务。独立 Cargo 工程与后端分开锁定依赖，避免将 CLI 发布绑定到后端构建。 源码开发需要 Rust；面向普通用户的签名二进制、安装器和更新渠道尚待发布， 当前没有声称普通用户已经能“一键安装”。CI 构建产物仅作开发预览，不自动发布。

退出码与安全边界#

退出码 含义
0 查询或可执行预览已输出，或受管操作已提交；请继续检查各层状态
2 参数不完整、目标未知、无法选择目标或输出失败
3 能力未实现、检查未完成或操作被阻止

restore_fields 是内存中的三方字段恢复算法：仅在字段仍等于 LMM 写入值时撤销， 保留用户后续修改；任一冲突使整个目标的计算失败。它拒绝整对象、数组及数组索引恢复。 该字段算法仍未连接应用配置写入；CC Switch 的 restore 默认恢复受管发行包版本，--configuration 按原生数据库回执恢复 LMM 配置。这些路径使用各自的持久日志、原生版本门禁和三方状态检查。 同样，付费检查函数只是客户端规划规则，不能代替服务端消费限制。

指纹函数只用于有界配置快照的内容比较，不是原子写锁。未来接入必须使用目标软件原生 事务/管理接口解决并发写入；“比较哈希后覆盖文件”不满足完整并发修改验收。

只读检查和 --dry-run 不建立状态目录；确认的受管安装建立自己的私有目录与无凭据日志。OAuth 操作使用独立锁与系统凭据库。 LMM 不复制第三方凭据、不上传遥测、不进行付费调用。 分享前建议使用 doctor --report --json；普通 status 会显示本地路径。
