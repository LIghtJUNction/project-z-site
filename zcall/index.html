zcall

协议无关的模型调用内核，由宿主提供传输与缓冲区。

A protocol-independent, caller-buffered AI call kernel for harness software. Default build: Rust 1.99.1 · Edition 2024 · no_std · core + zconv · no allocation · safe Rust · Sans-I/O.

The repository pins Rust 1.99.1 as its development toolchain and declared minimum compiler. The zconv 0.4.1 dependency uses the same minimum.

zcall::v1 gives a harness ordered requests, borrowed complete responses, unified stream events, explicit capabilities and a model-turn state machine. zconv owns protocol parsing and encoding. The harness owns transport, authentication, retries, scheduling, conversation history, tool execution and agent decisions.

The optional server feature adds a bounded std TCP/Unix HTTP server, strict JSON/SSE conversion, caller-key management and an extensible gateway. It adds no crate dependency: the host supplies upstream transport and optional request decompression. See the server boundary and integration guide.

Use#

toml
[dependencies]
zcall = { version = "0.4.2", default-features = false }

Development follows the canonical zconv Git default branch, with its exact source recorded in Cargo.lock. The 0.4.2 registry package pins zconv = "=0.4.1"; both declarations disable default features. Its dependency graph contains only zcall and zconv. The release workflow checks the actual registry dependency, package, name ownership and version before publishing; it never ships a Git-only or path-only dependency.

rust
use zcall::v1::*;

fn main() -> Result<(), Error> {
    let mut records = RecordStorage::<16>::new();
    let mut tokens = TokenStorage::<128>::new();
    // An explicit authoring contract governs defaults such as tool strictness.
    // Backend selection below does not change the message or business logic.
    let mut builder = RequestBuilder::new(
        Protocol::OpenAiChat.into(),
        Presence::Value(Text::new("caller-selected-model")),
        &mut records,
    )?;
    builder.message(Role::User, &[Content::text("Explain a hash table.")])?;
    let mut request = builder.finish();
    let mut output = [0; 1024];
    let report = request.encode(
        Protocol::AnthropicMessages.into(),
        &mut output,
        &mut [],
        &mut tokens,
        EncodeContext::default().with_max_tokens(256),
        Policy::default(),
    )?;
    // The harness sends output[..report.written] using its own transport.
    assert!(report.written > 0);
    Ok(())
}

Use Request::prepare when sending a model call: it derives requirements from the actual request, checks caller model/deployment evidence, and runs the target encoder. Request::encode is the lower-level conversion operation and makes no model-capability promise. Unknown model features or deployment limits remain unknown unless explicitly accepted, with a per-layer diagnostic report.

Base URLs and protocol discovery#

HttpEndpoint and Discovery are included in zcall. Use the versioned crates.io dependency above for reproducible installs.

Configure a known protocol with HttpEndpoint; it borrows the base URL and writes the final request URL into caller storage:

rust
use zcall::v1::*;

let endpoint = HttpEndpoint::new(
    "https://gateway.example/v1",
    Protocol::OpenAiResponses.into(),
)?;
let mut url = [0; 256];
assert_eq!(
    endpoint.url_into(None, false, &mut url)?,
    "https://gateway.example/v1/responses",
);
# Ok::<(), EndpointError>(())

For an unknown protocol, Discovery::new(base_url, model) generates bounded probe requests. Send each Probe with your HTTP client and pass its status, content type and body to Discovery::observe. The first candidate with a protocol-specific, schema-valid successful response becomes selected(). Credentials, timeouts and HTTP remain in your application. Each probe is a small generation request and may consume provider credits; discovery never replays your business request. Authentication, rate limits, server failures and unrecognized responses remain separate outcomes.

sh
# Generate all six endpoint styles without network access.
cargo run --example endpoint
# Use an existing curl executable and the API_KEY environment variable.
cargo run --example discover -- https://gateway.example/v1 your-model auto
# Explicit mode constructs the endpoint without sending a probe.
cargo run --example discover -- https://gateway.example/v1 your-model responses

See endpoint and discovery usage for URL rules, probe configuration, transport integration and caching. These APIs preserve the library's no_std, zero-allocation and sole-dependency contract.

Contract#

  • Requests, complete responses and events have separate types. Presence preserves missing, null and values; zero and empty remain values.
  • RecordStorage holds the actual zconv IR. Views borrow it; edits and appends write directly into it. There is no second copied request tree.
  • Session::step accepts arbitrary byte fragments and a backpressured event consumer. Control::Pause rejects the current event; retry sees that event again. Perform consumer side effects only when returning Continue.
  • Tools may interleave. ToolReady contains a complete validated JSON object; execution belongs to the harness. WaitingTools ends a model turn and still requires harness work.
  • Local cancel intent, confirmed cancellation, transport failure, upstream failure, malformed input and truncated input have distinct behavior.
  • Counters remain integers. Cumulative usage updates replace prior fields; cache and thought accounting use the shared zconv accumulator.
  • A capacity error names its storage region, required size, exactness and retry rule. Always advance stream input by SessionStep::consumed.
  • The v1 semantic contract is independent of zconv's public record layout and token types. Rust type layouts and cross-compiler binary ABI are not promised.

Implemented adapters#

OpenAI Completions, OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Gemini GenerateContent and Gemini Interactions have real request, response and SSE event adapters. Support is limited to representable semantics and tested versions/profiles. Unknown protocols require an implemented adapter in zconv and an explicit zcall integration with conformance tests.

zcall::api also exposes zconv's borrowed Embeddings, Images, Batch and Files codecs, endpoint paths and multipart writers. Use zcall::api::json for their caller-owned token workspace. These resource APIs remain separate from the six conversation protocols and do not send HTTP requests, upload files or execute batches.

Structured tool results expose typed child blocks through BlockView::result_contents. Author arrays with Request::append_tool_result_contents; their record spans belong to the current document and cannot be copied to another request. Request::stream_options preserves usage preferences, including preferences returned in EncodeReport::transport_stream_options for targets without that JSON field. Set EventEncoderConfig::usage_emission to UsageEmission::Continuous when intermediate observed counters are required. Missing counters stay absent.

BlockType::Reasoning carries raw reasoning and ReasoningSummary carries a summary. Anthropic source-owned blocks, citation deltas and usage metadata have explicit provider events. They can be replayed to the same format; server tool blocks never become local ToolReady work.

Strict conversion is the default. Provider context references, file IDs, opaque signatures and extension values retain their source namespace. When a target requires absent facts, the caller supplies them through an explicit context. Loss permissions are narrow and accompanied by inspectable field-level reports.

Build and verify#

sh
cargo test --all-targets --locked
cargo +1.99.1 test --all-targets --locked
cargo clippy --all-targets --locked -- -D warnings
python3 scripts/check_package.py
python3 -m unittest discover -s scripts -p 'test_*.py'

See examples/request.rs for backend switching, examples/stream.rs for the shared event consumer, examples/endpoint.rs for URL construction and examples/discover.rs for a runnable discovery client. The semantic contract, support matrix, resource recovery, dependency audit, measurements, validation evidence and release procedure describe the implemented boundaries.
