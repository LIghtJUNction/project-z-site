Daily workflow on Linux

The Linux shared runtime keeps the PTY and terminal model independent of its window. Search, command actions and configuration changes operate on that live session; they do not restart its child. The native macOS and Windows frontends do not implement the Linux search, session switcher, command palette or shared runtime. Windows implements font zoom and tab/split shortcuts in its native workspace; macOS does not yet implement font zoom or workspace UI.

Keyboard and command palette#

Shortcut Action
Ctrl+Shift+F Open history search; seed it with a single-line selection
Enter / Shift+Enter in search (including keypad Enter) Next / previous match, wrapping at the ends
F3 / Shift+F3 in search Next / previous match
Alt+C in search Toggle case-sensitive / Unicode lowercase matching
Ctrl+U or Ctrl+A in search/palette Clear the query
Esc Close the temporary search/palette
Ctrl+Shift+P Open the command palette; type to filter, arrows (including keypad Up/Down) to select, Enter (including keypad Enter) to run
Ctrl+Shift+S Find a session by name, title or URI; focus its view or explicitly attach
Ctrl+Shift+K / J Previous / next retained shell command
Ctrl+Shift+Y Copy the selected command's output; otherwise copy the latest output
Ctrl+Plus or Ctrl+Equal / Ctrl+Minus Increase / decrease font size
Ctrl+Shift+Minus Decrease font size while Shift is held
Ctrl+0 or Ctrl+Shift+0 Reset to the configured font size
Ctrl+keypad Add / Subtract / 0 Increase / decrease / reset; keypad 0 needs Num Lock on
Ctrl+Tab / Ctrl+Shift+Tab Next / previous workspace tab
Ctrl+Shift+R Reload the session's configuration file
Ctrl+Shift+C / V Copy selection / paste clipboard
Shift+PageUp / PageDown Scroll history

Plus follows the active keyboard layout, including Ctrl+Shift+Equal on common keyboards and a different shifted key on other layouts. Zoom changes the font and PTY grid within the existing pixel-sized window. Ctrl+0 restores the latest successfully loaded configuration font. With Num Lock off, keypad 0 keeps its Insert behavior. Split resizing uses Ctrl+Alt+Shift+Equal / Minus.

The native Windows reset shortcut is Ctrl+0. Windows can reserve Ctrl+Shift+0 when multiple keyboard layouts are active; that alias works only if delivered. Microsoft's shortcut guidance describes the system setting. The Linux shortcuts in the table remain available.

Custom bindings are checked before these defaults. For example, keybind = ctrl+shift+plus = none disables that shifted zoom chord, while keybind = ctrl+kp-add = font-decrease changes only Ctrl+keypad Add.

The palette appears only when requested. It uses the existing window and does not send its query or action keystrokes to the child. It exposes the same named actions as custom bindings and ztty action NAME ACTION. Filters accept several case-insensitive words in any order, and action rows show a currently effective shortcut, including custom overrides. Workspace shortcuts are listed in workspaces.

The session switcher labels existing views and detached sessions separately. Selecting an existing view focuses its actual window, tab and pane without changing its PTY or input owner. A detached session requires an explicit Attach entry. Observing views and sessions controlled by another actor remain read-only; switching does not take input ownership. The selected URI distinguishes sessions with the same display name. If a Focus target detaches while the list is open, the action reports that change rather than silently creating a new view.

Search uses literal UTF-8 matching across rows joined by terminal autowrap. Each search starts case-sensitive. Alt+C switches to Unicode lowercase comparison and back; the search bar displays the mode. Copying retains the original spelling. This comparison does not normalize accents or perform full Unicode case folding. Explicit line breaks remain boundaries. It highlights complete wide and combining cells, including the visible portion of a match extending outside the viewport. Queries are limited to 1,024 bytes; the streaming matcher retains one normalized query's positions, not a copy of the history. The highlight map uses one bit per visible cell, at most 16 KiB for a 512×256 grid.

Repeated Next/Previous navigation reuses the match count and up to 128 match coordinates while the query, case mode and terminal text revision are unchanged. The first search still scans retained text; moving beyond the cached window can scan again. Closing search releases its cache. See the bounded navigation measurements.

Copying a selection joins automatic line wraps while retaining explicit newlines. Wide-glyph wrap padding is omitted, meaningful spaces are retained, and UTF-8 cells remain whole within the 4 MiB selection limit. An active search can copy its complete match even when it spans more than a viewport. Output or a resize invalidates saved match coordinates; copying refreshes the search first.

Search does not provide regular expressions. Retained primary-screen text reflows across width changes using recorded soft wraps; hard line boundaries remain intact. Narrowing the screen can still evict history under the existing row and byte limits. Match counts refresh when editing, navigating or copying the query. Native macOS and Windows share the selection-copy rules, while their search and command palette interfaces remain unimplemented. See the core reflow contract and 0.5.2 release evidence.

Returning to live output#

Scrolling into history shows a small Back to live ↓ control near the lower right corner. Clicking it returns to the newest output and hides the control. The terminal keeps its full row count; there is no permanent toolbar at the live screen. Shift+PageUp/PageDown and the existing scroll actions remain available.

When the child produces more output while you are reading history, the visible rows stay anchored, including after the retained-history buffer reaches its limit, and the control changes to New output · Back to live ↓ with a blue border. If the inspected content is evicted, the view stops at the oldest row still retained. The indicator remains until the view returns to the bottom. Scrolling up again starts with the ordinary label, so an earlier output arrival does not appear as a new notification.

The control sits above an open search row or command palette. Clicking it keeps that interface open and preserves its input mode. It also works in an observing view without acquiring control or resizing the child. Its mouse press, drag and release stay within the view controls, including when the application requests mouse reports. In narrow views the label becomes Live ↓ or ↓; the control is hidden if a complete target cannot fit above the active interface.

Shell command regions#

Enable the appropriate script using shell/README.md. ztty shell-integration bash|zsh|fish|nu prints the packaged script, so it can be loaded explicitly without changing unrelated shell configuration. The scripts send OSC 133 prompt/input/output/end marks and OSC 7 working-directory metadata.

sh
ztty commands work
ztty command-output work 1

The CLI returns JSON. Command-output responses contain text, complete, truncated and command_id. MCP additionally accepts part: "input" and a max_bytes bound through session_command_read. At most 128 metadata records are retained; extracted text is limited to 65,536 UTF-8 bytes. Copying through the GUI refuses truncated output, so an incomplete region is not silently presented as a complete command result.

Command regions point into the existing terminal history. They are rendered text, not immutable stdout, and physical lines become newline separators. Overwriting/erasing text, changing the width of a live region or exhausting history can invalidate a region. Navigation skips unavailable records. Already retained, intact historical commands remain usable after a font change.

Bash hook acceptance#

The Bash integration preserves existing PROMPT_COMMAND strings or array entries, their exit-status behavior, and an inherited PS0 suffix. Repeated sourcing and nested shells must not duplicate execution marks. The dedicated PTY gate is part of the local Linux check; the four-shell gate also checks Bash syntax and the first source result independently of the second. Bash regression, old-script failure and exact versions record the current evidence. Bash before 5.1 has not been executed in this acceptance run.

Custom keys and mouse buttons#

Bindings are lines in the same configuration file as fonts and colors:

ini
keybind = ctrl+shift+x = search
keybind = ctrl+shift+p = palette
keybind = ctrl+shift+t = none
mousebind = ctrl+button3 = palette

Modifiers are ctrl, shift, alt, super. Keys include ASCII characters, f1–f35, enter, escape, tab, backspace, space, arrows, home, end, pageup, pagedown, equal/plus, minus, kp-add, kp-subtract, and kp-0. Mouse buttons are button1–button11. Binding comparisons ignore the Caps Lock and Num Lock modifier bits, but the active layout still resolves the key itself: keypad 0 is kp-0 with Num Lock on and Insert with it off. Custom bindings replace defaults for the exact chord. none consumes a chord without running an action. Each matched press and its release are withheld from application input, including buttons while an application has enabled mouse reports. There are at most 128 custom chords; unknown actions and malformed chords reject the config.

The palette lists action descriptions and effective shortcuts; exact binding names are in src/actions.rs. Selection, copy and navigation remain available while observing; paste requires local input ownership.

In ordinary shell mode, Caps Lock, Num Lock and Scroll Lock change keyboard state without sending private-use escape sequences. Programs that explicitly enable the enhanced keyboard protocol still receive negotiated lock-key events. With Num Lock enabled, keypad digits type numbers. With it disabled, keypad zero is the standard Insert key (ESC [ 2 ~), whose handling belongs to the application.

Live configuration#

The session remembers its explicit --config path, otherwise the default config path. Linux inotify watches the containing directory, including atomic saves. It follows replacement/recreation of that directory through the nearest existing ancestor and releases watches after their last session closes. There is no periodic idle polling. Manual reload is Ctrl+Shift+R.

Valid changes update fonts, padding, theme, cursor and selection colors, custom bindings and supported opacity/blur settings in the existing window. Invalid configuration retains the last valid state and shows a temporary error line. Font validation and PTY resizing precede the live appearance commit. A window created with an opaque visual needs detach/attach before enabling a supported transparent visual; an X server without an alpha visual retains its opaque fallback. Theme changes preserve explicit RGB colors and update default/ANSI colors using source flags in the existing cell.

Font reset returns to the latest successfully loaded config font. A font change preserves the PTY PID and window. Observing views cannot resize the child; their window appearance can still change independently.

Configuration-directory race regression#

A real GUI run exposed a missed reload when the config directory was renamed and rebuilt. A replacement directory could appear after the direct watch failed but before its ancestor watch was installed. If its file was then written after reconnect, the ancestor did not receive that child-directory write.

Reconnect now installs the nearest existing ancestor watch before probing each child directory again. It either reaches the new parent or keeps the watch that will report its future creation. This adds no polling timer or permanent extra watch. Shared descriptors remain alive until their last configured path is removed.

Three real inotify tests schedule this filesystem race precisely and use the real libc watch calls. The old implementation fails both race cases; the fixed implementation passes all three cases. The third case checks shared-descriptor retention and final release. See the source/test hashes and comparison record, old failure log, and fixed trace. The normal local gate now runs all Rust integration tests and MCP security tests.
