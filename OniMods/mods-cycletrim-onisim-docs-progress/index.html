OniSim engineering log

Current checkpoint (2026-11-20)#

The exact Linux x64 U60/763796 tuple is admitted after strict assembly, Mono, official Sim and ABI checks. Development source 8db2654 has actual-game evidence for six naturally formed oxygen/carbon-dioxide cells: complete inventories, mass, temperature and total mass match as binary32 bits after a unique checkpoint and same-process reload, followed by bounded advancement. See runtime validation for method, identities and the linked profile, actual-Mono and live receipts. These changes are not yet on Steam Workshop; Windows/macOS profiles remain limited to 744825.

Mixed saves now use version 0x4f4d0001 and a mandatory ONIMIX extension; ordinary single-inventory v15 images remain unchanged. The tested older OniSim rejects mixed images. The save contract records exact 22-species host/FFI round trips; live extra-species slots remain unverified. Whole-game performance A/B and long-duration/DLC acceptance remain open. The tested pressure values are placeholders; later fill, pressure-availability and background-run changes need their own actual-game validation.

The dated snapshots below retain their original evidence and limitations.

Status snapshot (2026-11-16)#

CycleTrim 0.4.24 corrects multicomponent region coverage at the final public row and column. Public coordinates are shifted by one into padded storage, so the interior occupies [1, width + 1) x [1, height + 1). Gas and liquid staging, species discovery, batch/idle keys, diffusion ownership masks and the thermal region map now share those exclusive upper bounds. The surrounding halo remains outside the regional operators.

Validation on the development machine:

  • Eight new boundary regressions pass, covering edge/corner gas expansion, per-species liquid conservation, exact mask dimensions, sleeping-region invalidation, batch wake-up and thermal ownership.
  • Gas direct/batch tests explicitly require the GPU path; Vulkan logs identify the NVIDIA GeForce RTX 4060 Laptop GPU. Sparse liquid and reference liquid diffusion both execute on that device.
  • The complete native Release suite passes: 229 passed, 0 failed, 19 ignored. The ignored cases retain their existing manual benchmark annotations.
  • The conservation fixture for a 4x4 public world now sums all sixteen cells; its original 1e-4 tolerance is unchanged.

This is native CPU/GPU correctness validation. No ONI process was launched in this iteration under the previously retained no-launch instruction. Whole-game FPS, save/load and long-duration acceptance are outside these results.

Status snapshot (2026-11-08)#

Runtime policy#

  • Since CycleTrim 0.4.5 OniSim is always mapped at startup; the PLib EnableOniSimExperimental toggle and the official-SimDLL fallback were removed. CYCLETRIM_ONISIM_ENABLE=0 is an emergency kill switch only.
  • CYCLETRIM_ONISIM_WORKERS defaults to 8 when unset (0.4.6).
  • 0.4.7/0.4.8: FLAG_MULTICOMPONENT_COEXISTENCE lets a second gas species share a cell when classic displace_gas fails; the multicomponent CPU upwind flux runs in the native tick. Saves still store the dominant element plus a runtime mixture overlay.

GPU pipeline#

  • GpuSimulation (wgpu 30, Vulkan) is created at engine construction unless CYCLETRIM_ONISIM_GPU=0; failure falls back to CPU with a log line.
  • Committed and in the tick: whole-grid thermal diffusion with resident temperatures and compressed mixture-presence uploads; regional gas multicomponent diffusion / pressure projection / transport / thermal chained between GPU buffers; sparse liquid multicomponent diffusion overlapped with the CPU gas-pressure pass; diffusion snapshots limited to the active region.
  • CPU-side tick changes: bubble simulation skips empty spans, liquid droplets settle, bubbles and droplets share one sparse scan, and idle zero-time frames reuse the previous publication.
  • Working tree (uncommitted): GPU bubble/droplet movement, phase-transition selection, gas pressure faces and liquid head/flow, disease diffusion and growth, radiation regions and inactive-cell decay are wired into simulation_step.rs behind systems.gpu, with the CPU functions kept as the no-GPU path. cargo check --release passes for the native crate. No unit test run, differential fixture or in-game log has been recorded for these passes yet.
  • Last game evidence: Player.log from 2026-11-08 00:26 reports GPU acceleration active on Vulkan device: NVIDIA GeForce RTX 4060 Laptop GPU (grid 738x306). It predates all 2026-11-08 commits listed above.

Open gates#

  • Per-step upload / device wait / readback remains; not a device-resident loop.
  • Pressure, partial-pressure and liquid-volume-fraction publication, three or more species per cell and full save/load of all components are incomplete.
  • No whole-game FPS, long-duration, DLC or other-Mod acceptance for the current source.

Status snapshot (2026-11-07)#

Message routing audit#

A static audit against OFFICIAL-MESSAGES.md found all 62 official message IDs referenced by the current native source. Fifty-nine route into lifecycle, world, cell-material, cell-command, thermal-component, mass-component, interaction or radiation handlers. SetVisibleCells, ToggleProfiler and RadiationSickness are explicit no-ops because they are absent from both dispatch registries in the pinned official 744825 library. This is identifier and dispatch accounting only; it is not proof that every message's complete gameplay semantics are equivalent.

Confirmed remaining gaps#

  • Elements_CreateInteractions is parsed and its rule records are retained in state, but do_gas_interaction and do_gas_interaction_pair have no caller in the Rust fixed-step pipeline. Static inspection of the pinned official control flow also found no incoming call to the legacy three-argument helper. Whether these helpers belong in the active simulation path is unresolved; do not add a guessed phase call without a positive official call-site or a differential behavior fixture.
  • The current source has no passing overall four-worker scaling gate. Worker creation and differential correctness do not prove a performance win.
  • The current source snapshot has no corresponding full-game graphical, long-duration or whole-colony acceptance. Historical receipts apply only to their exact source and binary identities.
  • The 29 ordered GameDataUpdate event queues are declared and published by events.rs; each individual callback still requires end-to-end behavior coverage, not merely a non-null span.
  • SIMSAVE v15 parsing/serialization and world-offset/topology handling exist; full multi-world DLC and long-running game compatibility remain separate acceptance gates.

Physical pipeline status#

The fixed-step path currently runs temperature exchange and state transitions, gas/liquid pressure traversal, disease diffusion, radiation-region updates, component updates and cell post-processing. Post-processing calls partial-melt, sublimation/off-gas and unstable-cell paths. The helper remains unconnected in Rust; its required role in the pinned official simulation is unresolved and must not be guessed or marked complete.

Safety and CI#

  • PR #568 changed the CycleTrim option to a new EnableOniSimExperimental key, default off. (Superseded by 0.4.5: the toggle was removed and OniSim is always mapped.)
  • The standalone loader was also default-off, requiring an explicit CYCLETRIM_ONISIM_ENABLE=1/true/on opt-in. (Superseded by 0.4.5 for the CycleTrim package; =0 remains the kill switch.)
  • The original tools/OniHarness gitlink pointed at an unreachable commit (107fee3c…). The PR pins reachable OniHarness main (c149819e…) so checkout can proceed. Checkout success alone is not test acceptance.
  • The Jlib submodule now pins 68e4935…. Its net48 FrameworkPathOverride is applied only when the supplied ONI Managed directory actually contains mscorlib.dll; a references-only directory therefore falls back to the installed .NET targeting pack.
  • The embedded SteamPublisher build smoke test still checks extracted files on every host. It compiles only when the game-shipped com.rlabrecque.steamworks.net.dll is available; otherwise it reports an explicit skip instead of treating a missing ONI installation as a Rust core regression. This is not a substitute for a game-installed publisher integration build.

The existing source checkpoint below records 47 passing Release Rust tests. It explicitly does not claim whole-game FPS/RSS, overall worker speedup or a current-source game launch. Older results below remain historical evidence.

Source checkpoint: inline thermal command queue#

The production thermal command queue now stores each validated fixed-size ABI payload inline in a 48-byte queue entry. Its 14 supported message types need at most 44 payload bytes. Individual commands no longer allocate a separate payload Vec, and energy batches reserve once and append directly without a temporary batch vector. The queue still owns copied bytes; caller buffer reuse cannot alter pending commands. Processing preserves type rank, arrival order within a type, the backwall boundary and the exact original message bytes, including float bit patterns.

All 47 Release Rust tests pass, including four new checks for owned payloads, ordering, batch ingestion and bounded rejection. This is a source-level allocation reduction. No whole-game FPS, RSS or one/four-worker speedup is claimed; short payloads can use more inline storage than their previous bare queue record. The four-worker overall performance gate remains open. No game was launched for this iteration, and the older binary hashes and runtime receipts below do not validate this changed native source.
