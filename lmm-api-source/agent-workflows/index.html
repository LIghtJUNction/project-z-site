Agent 工作指南

文档目录 · 仓库入口 · 技能目录

先确定交付目标，再读取、修改、验证和交付。当前任务只跟踪在新架构进度。

读取与实施#

遵守仓库与主线：记录分支、基准提交和本地修改，保留 并行工作，写共享分支前检查远端。只读受影响代码、调用方和匹配技能，不例行扫描 所有 PR、重读全文档或清理分支；未变化的背景、授权和决策直接沿用。

小任务直接修改，复杂任务保留短计划。并行确能减少等待时再拆分，交代目标、现状、 分支/PR 和文件所有权，协议字段指定一个修改方。共享工作树、输出目录、schema 和 生产切换不能盲目并行；1C1G 节点不同时跑重型构建。

按功能定位源码#

已有 markref 时使用 markref list 和 markref context model.recovery --max-bytes 8000 关联实现与测试；find 只查标记 及相邻注释，未命中再用 rg。默认只扫描已跟踪文件，新文件使用 --include-untracked， 不为搜索而暂存。改标记后运行 markref --include-untracked check；标签本身不提供业务验收。

测试与开发分开#

普通开发由开发方完成针对性自测并报告“自测通过、独立验收未执行”；不主动派 测试方、审查方或追加验证轮次。仅在用户要求验收、独立复验或项目收尾时，分别 指定开发方和独立测试方，冻结待测输入。开发方修复、自测，整合方审查交接，测试方 复现、保留证据并复验；开发者不能为自己的修改签署独立通过。

逐页覆盖、协议转换和缺陷交接见质量指南。mock、 真实数据库、进程、浏览器和业务链结果分别记录；未覆盖、未实现或受阻项保持未完成。 保留失败，不删用例、弱化断言或替换成固定成功响应来消除它们。

每批返回、修复交接和复验后更新进度；长任务读取实际队列、进程和证据，区分运行、 排队、待审、失败、待复验、通过及未覆盖。返回数量不等于完成数量，未设置定时 机制时不得声称开启自动推送，也不另建重复完成表。

按范围选择检查#

命令来自 justfile、根脚本和前端脚本； 工具准备见开发指南。

改动 首选检查 扩大范围的条件
文档、AGENTS.md、技能正文 python3 -B scripts/check-docs-brand.py --docs-only，差异和改动示例 改检查器才跑其自测；维护范围外链接另查
翻译值 写入工具校验、各语言差异和同步结果 调用方/类型变化加 Web 类型检查；布局变化看实际页面
Web TypeScript 受影响测试、文件格式/lint、mise exec -- bun run typecheck:web 导入、依赖、构建配置、资源或加载变化运行 mise exec -- just build-web
Rust 核心 受影响测试、格式检查，使用 services/core/Cargo.toml 公共接口或影响不明运行 mise exec -- just test-core；持久化需真实隔离库
Go 扩展 受影响包及调用方测试、格式与相关静态检查 共享宿主/接口变化运行 mise exec -- just test-go；嵌套数据库模块单独测
CLI 初始化 apps/cli，在子仓库执行相关检查 CLI 集成验收用 mise exec -- just test-lmm
组件归档构建器 python3 -B scripts/test-distribution.py 实际打包逻辑变化时构建并校验受影响组件
原生 Linux 打包 python3 -B packaging/linux/test_build.py -v 格式/安装行为变化加 test_native.py 和隔离安装
Docker 配置/通信 相关静态检查和 fixture 挂载、进程、网络或恢复变化做真实 Docker 检查
跨组件验收 质量工具中所需的一层 按验收目标执行，低层检查不代替完整验收

鉴权、余额、计费、资金权限、持久化和 schema 变化须验证相关拒绝、重复请求、 并发、失败及最终数据一致性；固定成功的内部替身不替代真实业务链。范围限于本次 触及的路径，不借机补齐整个模块的组合。

just check 包含格式、lint、类型、Core/Go/Web 测试及源码边界，不包含 CLI 和 全部独立数据库模块；just build-web 已含 bundle 检查。quick、related、full 有重叠，只选目标所需一层；related 即使改文档也跑固定 Core/Go 回归，full 仍有 独立业务和资源验收。既有失败、债务和验收规则保持有效。

文档检查器覆盖维护入口、技能路径/元数据和 README 徽章，其他链接、锚点及命令 行为另查。Logo 变化才运行完整资产检查，翻译工具变化才跑其自测；文案不触发 应用构建、数据库或全仓格式化，也不执行初始化、迁移、注册、支付示例验证文字。 法律实现、资源或打包变化执行相关法律/分发测试，普通政策文案按文档处理。

适度与停止#

没有对抗性审查，也无需为假想挑刺堆砌防御。只写当前任务与真实调用方需要的代码：

  • 不为未出现的情况增加校验、兜底、重试、吞错、兼容层、开关或抽象；在外部输入、 服务、权限、资金和持久化边界校验，内部信任类型与不变量。
  • 删除已被替代的路径；保留兼容须有实际调用方。不顺带重构、改名、改格式或加固 范围外代码，发现的问题记录即可。
  • 复用相邻测试，仅覆盖本次行为或缺陷；不测未改代码、框架自身、简单透传或纯 mock， 不为覆盖率枚举无业务意义的组合。

修改后跑一次首选检查；修复后只重跑失败项及受影响检查。输入未变的通过结果直接 复用，按上表或用户要求才扩大范围。同因失败两次，或遇环境、网络、权限及无关 模块失败时，保留命令和输出并报告，不绕路反复探测、不扩大修改来“改绿”。

请求行为已实现、针对性检查通过、差异已审查即可交付。列出未运行项和剩余风险， 不追加测试或审查轮次；用户明确要求完整验收时按质量指南完成对应 资金、权限及数据要求。

复用而不是重做#

复用结果必须绑定测试源码、命令、退出码、日志、配置与依赖；相关输入变化才重跑， 旧结果标明原版本，不能记为新提交执行。聚合工具仍按自身计划运行，无自动缓存保证。

打包先固定组件、架构、格式和来源；复用匹配产物及其原 SHA，不因读取失败重编译， 不给旧二进制换上新源码标签。详见打包与分发。测试机或 服务机不承担无关冷构建；pgroll、Docker 仅为相关任务准备。

贡献与交付#

保留公共合同；移除文件前查消费者和动态入口。职责调整遵守架构， 不恢复已删除单体代码来通过构建。保留 LICENSE、NOTICE 和来源归属；普通测试只用 隔离数据库、合成凭据，不使用生产账号或生产数据。漏洞报告遵循 SECURITY.md，公共报告不含秘密；社区规则见 CODE_OF_CONDUCT.md。

区分源码、依赖、网络和权限失败，读取仅做有限且适用的重试。写入结果不确定时先查 准确 ID，不能重复付款、发版或初始化。交付说明结果、范围、兼容影响、实际检查、 未验证项及提交/PR，并读回远端结果。远端前进时保留他人修改，只重查受影响差异。

遵守子项目先推送、父仓库后更新指针的顺序；合并、发布、 资金移动和生产操作各自需要对应授权，已给且未变的授权无需重问。构建、部署和完整 业务验收分别记录；交付后停止，不自动合入整条 WIP 或清理无关分支。

指导来源#

按需读取和清晰技能入口参考 OpenAI 的 AGENTS.md、 Skills、 Best practices及 Harness engineering。具体门槛由本项目规定。
